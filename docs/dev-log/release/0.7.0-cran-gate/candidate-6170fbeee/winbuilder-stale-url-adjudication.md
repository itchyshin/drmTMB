# Adjudication of the win-builder PNG URL finding

## Observation

R-devel and R-release report a 404 for
`https://itchyshin.github.io/drmTMB/articles/function-map-cheatsheet.png`,
attributed to `inst/doc/function-map-cheatsheet.html`. R-oldrelease does not.
The same stale link appeared in predecessor checks before the function-map
image and link were removed.

## Candidate-content checks

The candidate itself contradicts that attribution:

1. A complete extraction of the immutable tarball contains neither the PNG nor
   `inst/doc/function-map-cheatsheet.html`, and no candidate file contains the
   URL.
2. `vignettes/articles/function-map-cheatsheet.Rmd` contains neither an image
   include nor a full-size-image hyperlink.
3. A clean render of that source contains no reference to the PNG.
4. The returned R-release Windows binary contains no
   `doc/function-map-cheatsheet.html`.
5. With the public PNG URL independently returning HTTP 404, a fresh clean,
   network-enabled `R CMD check --as-cran --run-donttest --no-manual` of the
   exact `1d6445db…` bytes completed with only `New submission`; it did not
   report the PNG.

This is strong evidence that the devel/release line is stale win-builder
workspace or URL-cache residue from earlier same-package/same-version uploads,
not a URL shipped or generated by the final candidate. The exact server
mechanism is an inference and is not claimed as attested fact.

Archived proof:

- `local-url-note-recheck-00check.log` — SHA-256 `8454a87d3584b60328250ee149dabcb6d224cdfb75f2ff350f3711828ea87342`
- `local-url-note-recheck-testthat.Rout` — SHA-256 `929f82f8b11467fd1b1db95c695d0a62b38081ebb065caf39a18d4f38c52dad5`
- `function-map-cheatsheet-png-http-headers.txt` — SHA-256 `aaed9779c8f334c3fbe2604d54449ce9d1abfa4366fb648b360fdb4887ffa2dd`

No source repair is warranted: adding or changing a link would alter clean
candidate bytes to address content those bytes do not contain.

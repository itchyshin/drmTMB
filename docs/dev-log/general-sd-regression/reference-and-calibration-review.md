# Independent reference and calibration design review

**Scope and decision (2026-10-17).** I reviewed the scalar numerical reference, its pure tests, the single-seed sensitivity pilot, and the prepared native Bernoulli calibration harness as source. I did not run a fit or a remote job. The scalar logit/Bernoulli reference is mathematically appropriate for the bounded pilot, subject to the numerical checks below. The 3,000-attempt production campaign is **NO-GO** until the generator and artifact-integrity defects are repaired and retested. This review does not certify the native implementation or its inference.

## Reference equation and numerical scope

For one ordinary independent random-intercept cluster, the implemented reference is

\[
 \ell_g(\beta,\alpha)=\log\int_{-\infty}^{\infty}\phi(z)
 \prod_{i\in g}{n_i\choose y_i}
 p_i(z)^{y_i}\{1-p_i(z)\}^{n_i-y_i}\,dz,
 \quad p_i(z)=h^{-1}\{x_i^\top\beta+e^{w_g^\top\alpha}z\}.
\]

The standard-normal integration variable, binomial combinatorial term, logit softplus, probit `pnorm(..., log.p=TRUE)`, and omission of zero-count log terms are correct. Centering at a scalar joint mode rescales numerical integration; it does not turn the answer into a Laplace approximation. The result remains finite-tolerance adaptive quadrature. The pure tests cover the zero-SD conditional limit, probit-normal closed form, Bernoulli symmetry, count normalization, row permutation, and a tight-vs-default tolerance check. Those identities support the reference implementation but do not establish accuracy over every fitted parameter region.

One advertised tail is not stable for complementary log-log: `rate <- exp(linear); log(-expm1(-rate))` gives `-Inf` at sufficiently negative finite `linear` (for example `-1000`), although the log success probability is approximately `linear`. Add a log-rate asymptotic branch and a fixed-value negative-tail test before using this reference for complementary log-log. This does not affect the proposed logit-only production cell. Validate scalar `link` length explicitly so malformed vector inputs fail with a controlled error. The pilot should retain the maximum per-cluster `relative_error`, subdivisions, and default-vs-tighter *per-cluster* difference; agreement of summed objectives alone could conceal cancellation.

## One-seed adaptive-versus-Laplace pilot

`run-reference-pilot.R` uses a predeclared seed, an independent base-R scalar integrator, and the helper's correctly indexed group covariate. It compares the native objective at its fitted parameter vector with a separately coded scalar **Laplace** objective, then evaluates and minimizes the **adaptive-integral** objective. Different Laplace and adaptive MLEs are expected; the useful result is their measured displacement and objective difference, not exact equality. The reverse-SD-covariate perturbation is a good negative control. The fixed bounds, optimizer return, finite-difference gradient, and 1e-8 versus 1e-10 integration comparison are sensible pilot gates.

Conditional pilot **GO**: impose the predeclared 300-second wall cap (estimated 2–5 minutes), preserve a failure receipt if it reaches the cap, and ensure the native point has acceptable convergence, Hessian, gradient, and inactive SD clamp before interpreting the parameter displacement. The script currently saves `check_drm(fit)` but does not make these health items a gate. Record integration error diagnostics and the native/adaptive objective values before any assertion that can abort, so a failed check leaves an inspectable result. This pilot is one seed and cannot support a coverage or calibration claim.

## Production blockers and repairs

1. **Wrong generating SD by group.** In `native-calibration/worker.R`, `w` has one value per observation, but `w[group]` uses group IDs as positions in that observation vector. For group `g`, the generator therefore uses approximately `w_group[ceiling(g/16)]`, while the fitted model uses `w_group[g]`. The intended 160 distinct group-scale values collapse to about ten. Define `w_group <- seq(-1,1,length.out=groups)`, set observation `w <- w_group[group]`, and generate with `sd_group <- exp(alpha0 + a*w_group)` followed by `sd_group[group]*u[group]`; alternatively use `exp(alpha0+a*w)` directly per observation. Add a deterministic zero-noise design assertion that generated conditional probabilities use the same `w` passed to the fit. This is a production **NO-GO**, regardless of how many attempts finish.
2. **Prepared artifacts are hashed but not enforced.** `prepare.R` writes a manifest and source/runtime hashes, yet `run.py` checks only row count/index and `worker.R` does not compare its installed package, DLL, scripts, or manifest against the preparation receipt. A source edit or package reinstall after preparation can silently mix implementations in one campaign. Pin a manifest digest and exact installed/source hashes, verify them before launch and at worker start (or through an immutable staged installation with verified digest), and fail closed on mismatch. The design receipt says 7,200 seconds while the intended launch cap is 3,600 seconds; the final receipt must record the actual cap and command.
3. **Summary identity and validity are too permissive.** `summarize.R` takes the first row for a repeated result index and does not verify each result's `a`, replicate, or seed against the manifest, nor reconcile final worker state with the supervisor receipt. A stale or misplaced result can enter the wrong condition. Require one uniquely indexed result, matching manifest identity and final supervisor state; treat every mismatch as an invalid attempt and make the summary visibly fail its integrity gate. A valid interval should also require a finite independent Laplace-oracle discrepancy below a predeclared tolerance; the worker records this discrepancy but currently ignores it in `valid_interval`. Add negative self-tests for missing, duplicated, swapped-seed, wrong-condition, worker-error, timeout, and non-started rows.
4. **Runtime needs a measured bound.** At 3,000 cases and 16 workers, the 45–60-minute estimate leaves no buffer under a 60-minute cap. Measure a bounded representative pilot including profile computation, R startup, and serialized outputs. If the cap expires, preserve all 3,000 planned attempts and mark unstarted/unfinished cases as such; do not silently extend time or select only completed attempts. The 120-second per-case cap and process-group cleanup are appropriate if the Totoro launch confirms the resource limit.

## Predeclared inference decision

The proposed three conditions (`a=-0.5,0,0.5`), 1,000 planned attempts each, fixed `160 × 16` design, and disjoint seed streams are a legitimate finite test cell after repairing the generator. Coverage uses all planned attempts, counting every failed or invalid interval as noncoverage. The exact 95% binomial confidence interval for each condition's coverage must lie wholly in `[0.925,0.975]`; for the null all-attempt false-positive rate it must lie wholly in `[0.025,0.075]`. The exact lower 95% confidence bound for the valid-interval fraction must be at least `0.95`. The 95% Monte Carlo t intervals for mean log-SD-slope bias and mean relative `exp(alpha)` bias must each lie within `[-0.10,0.10]`, with their finite-estimate denominators displayed. These are stringent but coherent **predeclared decision margins**, not proof of general calibration. Keep conditional coverage and conditional null rejection visible; failures counted as no rejection can reduce the all-attempt false-positive rate. A finite-estimate bias that passes while fits fail is a survivor-only result, so the validity and integrity gates must pass jointly.

The current positive self-test checks only a synthetic 950/1,000 and 50/1,000 case plus basic timeout/error supervision. It does not exercise the DGP indexing, artifact pinning, or corrupted-identity cases. No production approval should follow from that self-test alone. After repairs, run the one-seed reference pilot and a small time/validity pre-run on the **exact** candidate installation; then freeze the manifest, source hashes, command, resource cap, and thresholds before the full campaign. Report all 3,000 attempt states and all failed fits. Neither a passing numerical reference nor a passing campaign in this one cell establishes every family/provider/engine combination in the wider SD-regression goal.

## Re-review of the repaired calibration harness (2026-10-17)

**Decision: GO for the bounded three-case pre-run; NO-GO for production qualification.** This is a source and pure-self-test review of `generator.R`, `integrity.py`, `prepare.R`, `worker.R`, `run.py`, `summarize.R`, and `self-test.py`, against the original review and `calibration-root-review.md`. I ran `python3 tools/general-sd-regression/native-calibration/self-test.py` from the worktree root; it returned `NATIVE_CALIBRATION_SELF_TEST_PASS` in 22.7 seconds. I ran no fit, profile, calibration worker, or remote job. The pre-run is for timing and failure-mode evidence only, with the three prespecified indices `1,1001,2001`; it cannot pass the 1,000-per-condition inference thresholds.

The generating equation is now correct: `w_group[g]` determines `sd_group[g] = exp(alpha0 + a*w_group[g])`, and the observation predictor and latent term both use the same `group` map. The self-test checks all 160 group SDs at each negative, null, and positive truth, and demonstrates that the former `w[group]` indexing gives the wrong answer for nonzero slopes. The prepared registry includes the full manifest, source files, installed R databases and DLL, and R executable; launch, worker, and summary recheck hashes. The subset keeps a byte-identical full manifest while recording three planned indices. Worker validity now requires finite independent Laplace-oracle discrepancy below `1e-6`; summary independently enforces that bound, zero supervisor exit, completed worker state, acceptable fit diagnostics, and a completed profile interval. An error or timeout result carrying `valid_interval=TRUE` is rejected by the summary. The self-test actually mutates source, manifest, and installed-library bytes; swaps a seed or truth; duplicates a result; removes a result or receipt case; and checks worker error, timeout, non-started, launch-error, and SIGTERM cleanup states. These controls support the bounded pre-run, though synthetic success rows do not validate fitted coverage.

Two campaign-qualification defects remain. First, `summarize.R` reports `attempted_process` but only computes coverage and its interval using the **planned** denominator, plus coverage conditional on valid intervals. It must also report attempted-denominator coverage and its exact interval, while retaining planned-denominator coverage as the decision measure. Second, `qualification_denominator_complete` checks only whether each condition has 1,000 *planned* indices. It does not require an uninterrupted final receipt or completion of the campaign; a near-complete stopped study could display passing threshold columns. `run.py` records SIGINT/SIGTERM as `interrupted` but its top-level `main()` still returns exit code zero afterward. Before production, add an explicit campaign-complete/qualification gate that requires all 3,000 planned indices and a noninterrupted terminal supervisor receipt, make interrupted/campaign-timeout launch exit nonzero, and ensure no individual threshold flag is interpreted as overall qualification. Failed completed attempts can remain in the all-attempt denominator and need not themselves prevent qualification when the predeclared valid-fraction and coverage rules account for them.

The hash list detects changed registered files but `source-hashes.csv` itself has no external immutable digest: replacing a file *and its registry entry* can rebaseline the prepared run. Record the registry digest outside the prepared directory at freeze time, and compare it at pre-run/production launch and summary. This is an audit seal, not a reason to delay the three-case timing run if its original registry digest is recorded before launch. The prepared absolute source/library paths also require a fresh preparation on the actual execution host; copying only the prepared directory to another host does not reproduce the installation identity.

For the bounded pre-run, use the command already recorded in `native-calibration-design.md` with `--workers 3 --case-timeout 120 --campaign-timeout 600`, after checking that its prepared directory, pinned library, and new subset-output path are present on the execution host. The stated 45–90-second estimate is a planning estimate; measure wall time and profile/failure receipts before sizing the full campaign. Production remains gated by those measurements, an acceptable three-case outcome, the reporting/completion repairs above, and a frozen source/registry/installation receipt. This review does not certify the native likelihood, profile inference, or calibration outside this single Bernoulli q1 cell.

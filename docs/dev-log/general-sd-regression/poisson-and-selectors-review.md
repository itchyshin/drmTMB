# Independent review: Poisson SD and selectors

**Review boundary.** Source-only review of the Poisson ordinary random-intercept SD path, its target resolution, TMB likelihood/reporting, and marginal-simulation override. No fits were run. This review does not certify calibration, production readiness, or the broader finite-universe programme. The independent test file `test-poisson-sd-integration.R` is treated as proposed evidence, not as executed evidence.

## Blocker

`split_tmb_parameters()` returns early for `model_type == "poisson"` with `mu` (and optionally `mi_*`) only; it does not split `par$beta_sd_mu` into the named SD coefficient entry. The adjacent binomial branch already performs this extraction (`R/drmTMB.R:22217-22243`). Since fit construction stores this result as `coefficients` and `coef.drmTMB()` reads `object$coefficients` (`R/methods.R:2322-2328`), Poisson SD coefficient extraction is absent. This conflicts directly with the new integration assertions and downstream consumers: `coef(fit, "sd(id)")`, the independent Laplace oracle, coefficient labels/vcov/profile targets, and target-specific bootstrap refits (`tests/testthat/test-poisson-sd-integration.R:10-27, 96-99`). Add the same target-aware split used by binomial for Poisson and cover scalar plus labelled selector targets; then rerun compiled tests. Until then the Poisson public output path is blocked even if the likelihood itself is correct.

## Bounded findings

- **Likelihood parameterization is internally coherent.** In the Poisson branch, each group has `eta_sd = X_sd_mu beta_sd_mu`; its SD is `exp(softclamp(eta_sd))`, which replaces the constant scalar SD only for rows mapped by `mu_re_sd_row` (`src/drmTMB.cpp:3962-4000`). The latent effect retains the standard-normal density, `dnorm(u, 0, 1, true)` (`:4003-4005`), so this is a log-SD regression rather than a change to the latent density. `beta_sd_mu` and group log/response SDs are reported, with fixed coefficients ADREPORTed (`:4009-4017`).
- **The family fence is explicit and narrow.** Poisson target resolution refuses any non-intercept random-effect term when an SD formula is supplied and checks target-group multiplicity before delegating to the shared identity resolver (`R/drmTMB.R:8617-8636`). The assembly tests exercise no-RE, slopes, zero inflation, missing responses, and within-group predictor variation (`tests/testthat/test-poisson-sd-assembly.R:38-60`). This supports only ordinary scalar random intercepts; it does not establish NB, ZIP, structured, slope, or correlation support.
- **Marginal simulation mapping is guarded.** The generalized override checks row-map length and validates mapped group rows before replacing only targeted latent SDs (`R/methods.R:7101-7139`). This is structurally appropriate for mixed targeted/untargeted intercept terms, subject to the missing coefficient extraction being fixed so prediction can obtain model coefficients.
- **Clamp diagnostics are not mislabeled as residual sigma.** Active fields add `log_sd_mu_group` for a random-scale model (`R/drmTMB.R:3643-3664`); Poisson is not added to the residual-sigma family list. The diagnostic therefore represents latent random-effect SD clamp status.
- **Constant-SD equivalence is a meaningful regression check.** The integration test compares the ordinary constant-SD route with `sd(id) ~ 1` on the same data, including likelihood, mean coefficients, and predicted group SD (`tests/testthat/test-poisson-sd-integration.R:52-60`). It is an implementation equivalence check, not a calibration result.

## Review disposition

**Blocked pending coefficient extraction and compiled retest.** The inspected TMB math and narrow selector fence are coherent for the proposed Poisson scalar-intercept slice. A passing source-assembly suite or the reported Totoro capsule cannot close the blocker unless it exercises `coef(fit, "sd(id)")` and its labelled-target counterpart against the corrected, freshly installed source. No inference about interval calibration or full programme completion is made here.

## Follow-up review of extraction repair

The extraction repair is now present. `split_tmb_mu_random_scale_parameters()` takes each registered `dpar` coefficient slice using `sd_mu$coef_index[[dpar]]` and assigns that target's registered coefficient names (`R/drmTMB.R:22217-22227`). Both Poisson and binomial route their ordinary SD parameters through this helper (`:22230-22249`), preserving the prior binomial selection behavior while supporting explicit keys and multiple target-specific offsets. The new source assembly test constructs two targets, checks distinct coefficient-index ranges, and compares each returned vector and names with the registry slice (`tests/testthat/test-poisson-sd-assembly.R:38-62`).

I ran `Rscript -e 'devtools::test(filter = "poisson-sd-assembly", reporter = "summary")'` from the isolated worktree. The five tests in that file passed (26 expectations; output was 26 dots and `DONE`). This is source-level assembly evidence only; no fitted model or compiled likelihood was exercised. The original blocker is resolved at source level; compiled integration still must pass with the corrected install, particularly named coefficient extraction and target-specific prediction/profile/bootstrap paths.

One reader-facing output limitation remains: `predict_parameters.drmTMB()` creates one long-table block per dpar, so differing group sets can have differing row counts without a false row-wise alignment (`R/predict-parameters.R:146-180`). However, when `newdata = NULL`, `predict_parameters_row_labels()` uses `"1"`, `"2"`, … (`:491-500`), discarding the names that `predict_random_scale_dpar()` returns from `group_levels_list`. Thus a random-scale prediction remains tied to the target by its explicit dpar key, but its default rows do not identify the group labels. Supplying group-level `newdata` retains its columns and row names, so the existing selector slice has a workable route; consider preserving group-level names in the default long output before describing those rows as self-identifying. This is a usability limitation, not a likelihood/extraction blocker.

**Updated disposition:** source-level extraction blocker resolved; bounded source test passes. Await corrected compiled integration test for a native-slice pass. Group labels in `predict_parameters()` remain a non-blocking reader-facing limitation. Calibration and broader programme status remain open.

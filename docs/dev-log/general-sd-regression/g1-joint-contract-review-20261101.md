# G1 independent joint contract review: latent-SD regression

Reviewer: independent read-only pass, 2026-11-01, on branch `codex/general-sd-regression` at HEAD `175e87560` plus the uncommitted working tree. This is the joint review that `.unlazy/general-sd-regression/GATES.md` (G1 entry) says is still missing after the literature synthesis in `notebooklm-review-2026-10-20.md`. It reads `g1-open-contract-review.md` (what remained open on 2026-10-17), `docs/design/18-random-effect-scale-models.md`, `docs/design/01-formula-grammar.md`, `docs/design/03-likelihoods.md`, `R/random-effect-targets.R`, `parse_sd_lhs()` in `R/parse-formula.R`, the SD predict and simulate code in `R/methods.R`, and the SD blocks of `src/drmTMB.cpp`. ## Overall verdict

Accept with conditions on all five areas. The native likelihood assembly is sound where it was checked: the diagonal scaling `Cov(b) = D C D` is implemented as the contract says, the correlated q2 Kronecker prior is algebraically correct, and several routes have independent oracles. The review found no defect that makes a currently admitted native route wrong. It did find (a) a gap between what the code does and what three documents and two roxygen blocks say about kernel scaling, (b) a diagnostic hole for the clamp on the `sigma` and second-structured SD blocks, (c) no general group-level SD design rank check, and (d) selector and key behaviour that is workable but not specified as a contract. G1 should stay open until the seven conditions at the end are met or are recorded as explicit limits. None of the conditions needs new simulation compute.

## 1. Formula selectors: sd(group, level =, dpar =, coef =, block =)

Contract as implemented. `parse_sd_lhs()` (`R/parse-formula.R:555-648`) accepts exactly one unnamed or `group =` symbol plus `dpar`, `coef`, `block`, `level` string options (lines 585-603). Explicit `dpar`, `coef` or `block` are refused unless the call was spelled `sd()` (lines 618-633), so `sd1()`/`sd2()` and the legacy `sd_phylo()` spellings cannot carry selectors. The legacy phylo spellings reject `level` (lines 681-694). The generic spelling `level = ` canonicalises to `sd_phylo`, `sd_animal`, `sd_relmat` or `sd_spatial` (lines 665-731), and for structured functions the selectors are parsed but then stripped from the public key (lines 647-651). The ordinary public level is implicit: `"group"` is not in the accepted level set at `R/parse-formula.R:705-707`, although the internal identity map labels ordinary members `level = "group"` (`R/random-effect-targets.R:92`).

Resolution is by `drm_resolve_sd_target()` (`R/random-effect-targets.R:115-243`). It filters members by group, level, `dpar`, `coef`, `block` and returns the single survivor, or aborts with the list of candidates ("Ambiguous ... Matching targets", lines 237-242). Duplicate targets are caught at `R/random-effect-targets.R:369-377`. Structured entries are resolved separately in `parse_sd_phylo_entry()` (`R/drmTMB.R:17567-17679`), which checks provider level, `dpar` equal to `mu` only, coefficient membership, block label, and group. The three q2 builders (Gamma `R/drmTMB.R:6860-6881`, Beta `R/drmTMB.R:7536-7566`, Binomial `R/drmTMB.R:9258-9285`) each require exactly one formula per coefficient and re-key the entries with `dpar = "mu", coef = ...`.

Docs match. `docs/design/18` (the Gamma q2 example near line 125) and `docs/design/01` (rows 221-230) show the same `coef`-selected spelling. The grammar document states that `sd1`/`sd2` refuse selectors, which matches line 618.

Risks.

1. The key is the user's spelling, not a canonical identity. `format_sd_lhs_dpar()` (`R/parse-formula.R:733-745`) writes only the selectors the user supplied, in a fixed order. Therefore `sd(id) ~ w` and `sd(id, coef = "(Intercept)") ~ w` name the same latent coefficient but produce two different parameter keys, two different `coef(fit, key)` names, and two different `predict(fit, dpar = key)` strings. Failure scenario: a script written against `sd(id)` breaks when the author later adds a second same-group slope formula and is forced to write `coef =`, and a saved profile target or a reproducibility artifact no longer matches. For structured q1 routes the key silently drops a supplied `coef` or `dpar` (`R/parse-formula.R:647-651`), so a single-formula fit keyed `sd_animal(id)` becomes keyed `sd_animal(id, dpar = "mu", coef = "x")` once a second formula is added (Gamma/Beta/Binomial re-key blocks above). The key therefore depends on the number of formulas.
2. `level = "group"` is rejected publicly (`R/parse-formula.R:705-731`) while the resolver treats it as the ordinary level. The 2026-10-17 review asked for one canonical spelling and an alias rule before lifting gates; that rule does not exist yet. Today an ordinary term has no way to be named explicitly when a structured term shares its group column, other than relying on the absence of `level`.
3. `block` is parsed and checked (`R/drmTMB.R:17650-17661`) but every admitted ordinary route requires an unlabelled block (`R/random-effect-targets.R:286,294,333,346`), and the Gamma q2 labelled route takes `coef` selectors, not `block`. So `block` has no admitted live use; it only improves error messages. That is acceptable, but the grammar document should say it is reserved.
4. `predict(fit, dpar = key)` goes through `match.arg(dpar, names(object$coefficients))` (`R/methods.R:3028`). It does partial matching on a string with parentheses and quotes, so a prefix typo can resolve to a different SD formula when keys share a prefix. Low severity, easy to harden with `exact = TRUE` semantics.
5. When an ordinary route is asked for `sd(id) ~ w` and the only term on `id` is structured, the message says "Add an ordinary `(1 | group)` term" (`R/random-effect-targets.R:270-273`) and does not mention `level =`. This is a usability defect, not an identifiability one.

Duplicate-coefficient handling is guarded in all three q2 builders by `anyDuplicated(selected)` plus `setequal` (Gamma and Beta) or `length != 2` (Binomial). Poisson and NB2 q2 coefficient-SD routes do not exist, so there is nothing to test there.

Verdict: accept with conditions (C2 below). The resolver is strict and lists actual candidates, which is the behaviour the contract wanted; what is missing is a written canonical key and alias rule, and a test that two spellings of the same target either map to one key or are documented as different.

## 2. Identifiability assumptions

Contract as implemented.

SD predictors constant within group: `validate_sd_mu_group_constant()` (`R/drmTMB.R:20215-20243`) runs for the ordinary builder (`R/drmTMB.R:19907`) and the structured builder (`R/drmTMB.R:20080`). The structured builder first rewrites phylo-interaction groups to pair labels (`R/drmTMB.R:20042-20064`). Complete-case filtering includes the SD formula variables (for example `R/drmTMB.R:4747-4749`, `5516`, `5884`, `6722-6726`), so an NA in an SD predictor drops the whole observation from the fit, including from the mean model. That is a consequence worth stating, because it changes the fitted sample, but it is consistent across the builders sampled.

Group-level design rank: there is none in the general SD builders. `build_sd_mu_structure()` (`R/drmTMB.R:19873-19988`) and `build_sd_phylo_structure()` (`R/drmTMB.R:19990-20212`) build `model.matrix()` on the group-first rows and never check `qr(X)$rank` or `nrow(X) >= ncol(X)`. The only rank check is hurdle NB2 (`R/drmTMB.R:11571`). The runtime `fixed_effect_rank_deficiency` diagnostic is for the fixed-effect designs, not these.

Slope identifiability: `validate_gamma_animal_q2_sd_identifiability()` (`R/drmTMB.R:15699-15741`) refuses an identically zero slope loading, and refuses a globally constant slope loading when the two SD designs are the same single constant column. It is called from the Gamma, Beta and Binomial structured q2 builders. Nothing equivalent covers ordinary correlated q2 or other shapes.

Singleton groups: `R/drmTMB.R:18000` and `19742` refuse a grouping variable with only singleton groups, as a software fence. The 2026-10-17 review asked that such fences be recorded as software fences, not as mathematical exclusions.

Kernel scaling and the 2026-10-24 decision are covered in section 3.

Docs match, partly. `docs/design/18` states the within-group constancy rule (around line 320) and the constant-slope refusal (line 140). It does not state the missing rank check, and it does not state the NA-drops-observation consequence.

Risks.

1. Rank-deficient SD design. Failure scenario: `sd(id) ~ w1 + w2 + w3` with 3 groups, or two collinear group-level predictors. `model.matrix()` returns a rank-deficient `X`, the optimiser sees flat directions in `beta_sd_mu`, the Hessian is singular, and the user gets a convergence or non-positive-definite warning with no pointer to the cause. For the structured routes the design is on observed provider levels only (`R/drmTMB.R:20046-20047`), so a pedigree with many ancestors but few observed animals can have `ncol(X)` close to or above the number of rows even though the kernel is large.
2. Weaker-than-fenced near-aliasing in q2. The fence covers only identical constant SD designs with a constant loading. With a constant slope loading and the same non-constant `w` on both coefficients, the marginal contribution is `tau0(w) u0 + c tau1(w) u1`, whose covariance is a sum of three exponentials in `w` weighted by `exp(2 a0)`, `c^2 exp(2 b0)` and `rho c exp(a0 + b0)`. That is locally identified only through the variation of `w`; with few groups it is close to unidentified. The fixed-seed tests use 40 groups by 16 observations and a loose 0.4 band on rho (`tests/testthat/test-gamma-animal-q2-correlated-sd.R:117-160`), which supports wiring and not identifiability. The 2026-10-17 note already said full-rank `W` is necessary and not sufficient; the code agrees, but the user-facing message path for weak information is only the generic Hessian diagnostic.
3. A silent unselected-axis scale. In the structured q2 coefficient route `field_effect` is multiplied by the SD row only `if (sd_row >= 0)` (`src/drmTMB.cpp:3534-3540`), and the constant `log_sd_phylo` is not used when `has_sd_phylo_model == 1`. A row with no SD map therefore gets unit scale, not an estimated constant SD. The R gate that turns the coefficient route on checks only `all(colSums(map >= 0) > 0)` (`R/drmTMB.R:25248-25250`), that is, at least one mapped row per coefficient, whereas the Binomial gate requires every observation to be mapped (`R/drmTMB.R:25217-25227` and `9512-9519`). In practice the builder maps every observation (`R/drmTMB.R:20108-20111`), so I could not construct a live failure, but the invariant lives in two different gates. A future provider whose SD group differs from the observation group would produce a silent unit-scale axis. This conflicts with the invariant "an unselected axis retains its existing constant SD".
4. Probit and Bernoulli singleton identity is correctly scoped as a special case in `notebooklm-review-2026-10-20.md`; the code fences are not claimed to be mathematical theorems anywhere I read. No finding.

Verdict: accept with conditions (C1, C6 below). The constancy rule is enforced, but the programme claims an "identifiable where possible" universe and has no general rank or information guard for the SD design.

## 3. Kernel scaling consistency across families and providers

Contract as implemented in the native engine. The structured field is stored at unit scale with precision `Q_phylo`, and the SD multiplier is applied afterwards, so `b = D u`, `u ~ N(0, Q^-1)`. In the single-field branch `field_effect *= sd_phylo_group(phylo_mu_sd_row(i))` and the prior is `0.5 * (n log 2 pi - log det Q + u' Q u)` with no SD term (`src/drmTMB.cpp:1384-1409` and `1470-1480`; same pattern at `3601-3625`, `4017-4090`, `5188-5300`). The supplied covariance is not rescaled: the unconverted-`K` oracles in `tests/testthat/test-structured-sd-nonunit-k-and-missing.R` (described in `docs/design/18` near line 1160) differ from the `cov2cor(K)` oracle by more than 0.05, so a silent normalisation would be caught. The marginal SD is therefore `tau_g sqrt(C_gg)`, and `predict(dpar = "sd(...)")` returns the multiplier `tau_g`.

Per provider on the native side:

- `phylo()`: `C_jj = 1` at every tip by construction, because the Brownian covariance is divided by tree height and the tree must be ultrametric (`R/formula-markers.R:190-215`). The multiplier is the marginal SD.
- `animal()` with `A`, `Ainv` or `pedigree`: raw relationship scale, `C_jj = A_jj` (1 plus inbreeding). Multiplier and marginal SD differ by `sqrt(A_jj)` for inbred animals.
- `relmat()` with `K` or `Q`: raw, `C_jj = K_jj` or `(Q^-1)_jj`.
- coordinate `spatial()`: `exp(-d / median(d))` plus a `1e-6` diagonal jitter (`R/drmTMB.R:17359-17379`), so `C_jj = 1 + 1e-6`, effectively unit. The jitter is fixed and undocumented in the user text.
- mesh spatial: a sparse GMRF projected through `A`; the reported SD is the raw GMRF multiplier and is not a constant marginal SD (`R/drmTMB.R:25916-25925` comment). Marginal simulation scales the projected value by the site multiplier (`R/methods.R:7767-7773`), which matches the stated `D_obs A Q^-1 A' D_obs` contract from 2026-10-17.
- `phylo_interaction`: Kronecker of two kernels; I did not verify its diagonal.

Docs and code disagree in three places.

1. `R/julia-simulate.R:13-15` and `R/methods.R:3176-3178` (the simulate roxygen, rendered to `man/`) say Julia Gamma animal simulation uses "the unit-diagonal correlation matrix used by the Julia fitter, including when the supplied relationship matrix has a non-unit diagonal" and "The Julia fitter normalizes the supplied relationship matrix to a correlation matrix". The programme invariant in `LOOP/lanes/general-sd-regression/GOAL.md` records the explicit 2026-10-24 decision that Julia Gamma animal models use supplied raw `A` to match native TMB. These cannot both be current. Either the roxygen is stale or the decision has not reached the simulator. I could not tell which from this tree; the test `tests/testthat/test-gamma-animal-q2-nonunit-kernel-parity.R` (titled "agree with raw non-unit kernel scaling") needs a live Julia and was not run.
2. `GATES.md` records, under 2026-10-22 Poisson evidence, that "Julia normalizes `A` to unit diagonal; native TMB retains supplied `A` scale". The sibling Julia worktree now documents the opposite for Poisson (`../general-sd-julia/src/poisson.jl:70-75`: the SD multiplies the supplied `A`, "non-unit diagonal values in `A` affect the marginal SD"). That GATES line is superseded but not marked so.
3. `docs/design/03-likelihoods.md` near line 2495 says the Gamma q2 test file has "no likelihood oracle". The test now contains a joint-objective oracle at 1e-6 with five emulated bugs (`tests/testthat/test-gamma-animal-q2-correlated-sd.R:174-217`). The docs understate the evidence, which is the safe direction, but `docs/design/18` line 1140 repeats "no oracle" in the 2026-11-01 table.

Cross-family and cross-engine inconsistency that the contract does not yet name. The Julia sibling worktree shows at least three conventions: NB2 animal rescales `A` to a correlation matrix before the SD multipliers (`../general-sd-julia/src/negbinomial.jl:81-84`), Poisson animal multiplies raw `A`, and the Gaussian residual diagnostic assumes unit diagonal (`../general-sd-julia/src/gaussian_core.jl:1659-1661`). The native engine is raw throughout. So a non-unit-diagonal NB2 animal model has a different latent covariance under `engine = "julia"` than under `engine = "tmb"`, in the same family, for the same formula. The invariant sentence "Gamma `relmat(K)` and other routes retain their established conventions" does not say what those conventions are. The Gamma q2 parity test compares engines at a relative tolerance of 0.25 on SD coefficients (`tests/testthat/test-gamma-animal-q2-nonunit-kernel-parity.R`, tolerance arguments), which is a loose check of a scaling decision.

Risks. A user who fits the same non-unit-diagonal pedigree under both engines can see SD coefficients shift by `log sqrt(A_jj)` per node, and the intercept will absorb the average, which looks like agreement on slopes with a disagreement on the intercept. A parity test with a unit-diagonal kernel cannot reveal this, and most existing parity fixtures are unit-diagonal.

Verdict: accept with conditions (C3 below). Native scaling is consistent and well-tested against unconverted kernels. The contract needs a per-provider, per-engine scaling table, and the three documentation contradictions must be resolved.

## 4. Prediction semantics: predict(fit, dpar = "sd(...)") and simulate(re.form = NA)

Contract as implemented.

`predict()` routes an SD key to `predict_random_scale_dpar()` (`R/methods.R:3047-3054`, `7020-7080`). With no `newdata` it uses the stored group-level design `X_list[[dpar]]` and names by group level; with `newdata` each row is treated as one group, rows are prepared against the fitted terms and levels, and non-finite design values abort (`R/methods.R:7049-7058`, `6321-6334`). It then applies the same soft clamp as the likelihood (`drm_softclamp_log_sd()`, `R/drmTMB.R:26688-26710`, which mirrors `src/drmTMB.cpp:27-53`) and exponentiates with the overflow guard. So `type = "link"` is the clamped log multiplier, not `X %*% coef`, and `type = "response"` is its exponential. The clamp is exactly the identity inside `[-12, 12]` and saturates smoothly to `[-15, 15]` (`R/control.R:111-120`, `src/drmTMB.cpp:17-35`). The overflow guard at 700 (`src/drmTMB.cpp:61-69`) is unreachable while the clamp is on.

The raw-report contract. `drm_softclamp_log_sd()` carries a comment that `log_sd_mu_group` reports the raw linear predictor so the fit-time check can see out-of-band values (`src/drmTMB.cpp:39-45`). That is true for the ordinary `mu` blocks (for example `src/drmTMB.cpp:2916`, `2999`, `3164`, `3255`, `3477`; 18 sites assign `log_sd_mu_group(g) = eta_sd`). It is not true for the other SD blocks: `log_sd_phylo_group` (`1391`, `3516-3530` and 10 sites in all), `log_sd_sigma_group` (`1275`, `3361`, `3647`) and `log_sd_phylo2_group` (`4879`) store the clamped value. So `ADREPORT(log_sd_mu_group)` has a delta-method derivative of the raw predictor, while the phylo and sigma ADREPORTs have a derivative that is zero outside the band. Inside the band they are identical, so no in-band result changes.

Fit-time clamp diagnostics. `drm_active_logsigma_clamp_fields()` (`R/drmTMB.R:3999-4020`) lists `log_sd_mu_group` and `log_sd_phylo_group` only. The start-value check (`R/drmTMB.R:1980-1995`) uses the same two names. Detection for the phylo block still works because the clamped value saturates at 15, which is above the band edge 12, but the reported value is the clamped one, not the raw one. There is no clamp-hit check at all for `log_sd_sigma_group` or `log_sd_phylo2_group`.

Marginal simulation (`re.form = NA`). Ordinary location SDs: `drm_ordinary_sd_effect_override()` (`R/methods.R:7451-7498`) maps each latent coefficient to its group SD through the stored zero-based row map, and leaves other terms at their constant SD, matching the C++ rule at `src/drmTMB.cpp:1244-1252`. Structured q1: `drm_structured_mu_random_effect_draws()` (`R/methods.R:7642-7742`) draws `u = R^-1 z` from the Cholesky factor of the stored precision and multiplies by a node SD vector; nodes with no SD row get 1 (`R/methods.R:7690-7698`). Because the scaling is diagonal this does not alter the covariance among observed nodes (`D_obs C_obs D_obs`), so I rate it correct. Structured q2: marginal simulation is allowed only for Binomial `relmat`/`animal` with no estimated correlation (`R/methods.R:7527-7550`, with `length(object$corpars) > 0L` returning NULL), and each coefficient field is drawn independently (`R/methods.R:7610-7622`). All other q2 structured fits, including every correlated Gamma q2 fit, are refused by `drm_structured_mu_marginal_unsupported()` (`R/methods.R:7518-7534`). The simulate documentation lists this limit (`R/methods.R:3195-3205`).

Docs match, partly. `docs/design/18` (around line 320) documents the `newdata` and `type` behaviour of SD predictions and the response-equals-exp-of-link rule. The `predict()` roxygen documents the clamped `sigma` (`R/methods.R:2982-2990`) but says nothing about SD parameters: that `link` is clamped, that SD predictions are multipliers on structured effects, and that `newdata` rows are group-level rows. The explanatory comment for the SD clamp exists only as a code comment (`R/methods.R:7063-7071`), and it cites stale line numbers (`src/drmTMB.cpp ~2482-2485`, `R/drmTMB.R:23062-23092`).

Risks.

1. Silent clamp on `sigma` SD routes. Failure scenario: a Gamma or NB2 `sd(id, dpar = "sigma") ~ w` fit where the latent log-CV SD runs to a boundary. The likelihood is flat beyond 15, the fit can report spurious convergence, and no `logsigma_clamp_active` note appears because the field name is not in the list. The same applies to the second structured Binomial field. This is a concrete gap in a safeguard that exists for the other two blocks.
2. Estimate and standard error disagree for the `mu` block outside the band. `predict(type = "link")` returns the clamped value while the ADREPORT of `log_sd_mu_group` is the raw linear predictor. Only reachable when the clamp binds, which is also when `check_drm()` should be warning, so the practical exposure is small. It is still a contract inconsistency between blocks.
3. A fallback that depends on an absent name. In `drm_structured_mu_random_effect_draws()` the modelled-SD path is reached only because `object$sdpars[[sd_key]][label]` is empty or NA for an SD-modelled fit (`R/methods.R:7656-7664`, then the fallback at `7665-7699`). `split_tmb_sdpars()` writes modelled SDs under the SD-formula key, not under `mu` (`R/drmTMB.R:25849-25862`), so the lookup is empty today. If a future change adds an unmodelled constant SD for another endpoint under `mu` with the same label, the simulator would silently use that constant instead of the per-node SD. Add an assertion tying the fallback to the registry.
4. `predict()` never returns the marginal SD `tau sqrt(C_gg)`. For inbred pedigrees or unit-height violations a user who reads the prediction as an SD will be off by `sqrt(A_gg)`. The vignette states the multiplier rule (`vignettes/predictor-dependent-random-sd.Rmd:52`, `917`, `1237`, `2046`), and `03-likelihoods.md` near lines 2367 and 2427 does too, so this is documented in prose but not at the function the user calls. The 2026-10-17 note said a new public marginal-SD name must follow the `predict_parameters()`/`VarCorr()` audit; that audit has not been recorded.
5. Newdata semantics for structured SDs. A `newdata` row has no kernel node, so a structured SD prediction for a new level is a population multiplier only, with no `sqrt(C_gg)`. This is coherent but undocumented.

Verdict: accept with conditions (C4, C5, C7 below).

## 5. The 2026-11-01 per-coefficient SD routes (correlated q2, rho = 0.999999 tanh(eta))

Contract as implemented. For a labelled `animal(1 + x | p | id)` term with two `coef`-selected SD formulas, the two latent fields are stored at unit scale, the per-observation SD row is applied to each field, and the prior is `N(0, R kron A)` with `R = [[1, rho], [rho, 1]]` and `rho = 0.999999 tanh(eta_cor_phylo)` (`src/drmTMB.cpp:3553-3586`). The negative log density is `0.5 * (2 n log 2 pi + n log(1 - rho^2) - 2 log det Q + (q11 - 2 rho q12 + q22) / (1 - rho^2))`, with `q_ab = u_a' Q u_b`. I checked this by hand: the precision of `R kron A` is `R^-1 kron Q`, `log det (R kron A) = n log(1 - rho^2) + 2 log det A`, and `R^-1 = (1 / (1 - rho^2)) [[1, -rho], [-rho, 1]]`. All three terms are correct. The SD parameters do not appear in this term because they enter only through the observation-side multipliers, which is the non-centred form the 2026-10-17 note asked for. The cross-node covariance is `rho tau0_g tau1_h A_gh` and the same-node correlation is `rho`, which is invariant to `D` and to `A_gg`. The C++ raises a runtime error unless both coefficient SD formulas exist (`src/drmTMB.cpp:3558-3560`). In R the flag is set only for labelled intercept-and-slope terms on Gamma, Poisson or NB2 (`R/drmTMB.R:23361-23368`); Poisson and NB2 reach their own blocks, and NB2 with SD errors out if q2 covariance is on (`src/drmTMB.cpp:5582-5584`), so the coefficient-SD correlated route is Gamma only.

Evidence. A joint-objective oracle written in R matches the TMB joint objective to 1e-6 on three fixed seeds, with five emulated bugs each moving it by more than 1e-3, and the unlabelled fit matches the same oracle at `rho = 0` (`tests/testthat/test-gamma-animal-q2-correlated-sd.R:174-217`). Recovery of rho uses a 0.4 band on three seeds. These are good likelihood-assembly checks.

Docs match, partly. `docs/design/03-likelihoods.md` near line 2495 gives the same formulas as the code and calls the test a "wiring check ... no likelihood oracle", and `docs/design/18` line 1140 says "no oracle". Both are now out of date in the conservative direction. `docs/design/18` correctly says Julia Gamma q2 remains independent and native only.

Risks.

1. Oracle fixture has a unit-diagonal kernel. The oracle fixture uses `A <- 0.45^abs(outer(...))` with diagonal exactly 1 (`tests/testthat/test-gamma-animal-q2-correlated-sd.R:1-8`). A bug that normalises `A` to a correlation matrix or that applies `1/A_gg` would not move that oracle. The raw-`A` decision for q2 is checked only in the Julia parity test, which is skipped without a live Julia and runs at 0.25 relative tolerance. Failure scenario: a refactor that routes the q2 labelled term through a correlation-normalised `Q` passes the whole native test file. The non-unit-diagonal native q2 oracle is a missing, cheap test.
2. Base-fit nesting is unavailable. The 2026-10-17 note required showing that the base q2 fit is recovered when SD slopes are zero. For Gamma there is no base labelled q2 route without `sd()` (a labelled term without SD formulas is refused, `R/drmTMB.R:6842-6852`), so nesting against a plain correlated fit cannot be shown. The oracle and the independent unlabelled fit stand in. That is acceptable only if the contract says so.
3. rho bound inconsistency. The structured q2 route bounds rho at `0.999999` (`src/drmTMB.cpp:1419`, `3562`, `5215`) while ordinary correlated blocks bound it at `0.99999999` (`src/drmTMB.cpp:1233`, 18 sites in all). The reported correlation and its profile or Wald behaviour at the boundary differ between routes. It is a documented number in `docs/design/03-likelihoods.md` but not flagged as a deliberate difference.
4. No refit identity for q2 correlated fits. Marginal simulation is refused for these fits (section 4), so the "marginal simulation/refit identity" check that the 2026-10-17 note required cannot be run on this route. The route is therefore evidenced by a likelihood oracle and recovery only, not by a simulate-then-refit loop.
5. Constant `log_sd_phylo` parameter. With `has_sd_phylo_model == 1` the template reads `log_sd_phylo` only in the non-SD branches. I did not verify that it is mapped off for these fits; if it is not, the objective has a flat parameter. The tests pass with Hessian availability, so it is probably handled, but it is the sort of thing the oracle cannot see. Mark as to-verify.

## Frozen production design

The production target is the native ordinary q1 Bernoulli random-intercept SD regression
`bf(y ~ x + (1 | id), sd(id) ~ w)`, with `binomial(link = "logit")`. Each condition uses 1,000 independent replicates at `a = -0.5, 0, 0.5`. Generate 160 groups with 16 Bernoulli observations per group, `w` equally spaced from -1 to 1, `x ~ N(0,1)`, and independent `u[g] ~ N(0,1)`. Set `log(s[g]) = log(0.8) + a*w[g]` and `Pr(y=1) = logit^-1(-0.3 + 0.6*x + s[g]*u[g])`. The manifest records fixed coefficients `beta=(-0.3, 0.6)` and `alpha0=log(0.8)`. Production seeds come deterministically from master seed `2026101703`; `prepare.R` reproduces and excludes every seed from the pilot stream generated from `2026101702`.

`prepare.R` has explicit `production` and `--qualification` modes. Production uses master seed `2026101703`; qualification uses the disjoint master seed `2026101704`. Both create all 3,000 manifest rows, and prepare verifies both streams are disjoint from the pilot (`2026101702`) and each other. Qualification is restricted by the runner to indices `1,1001,2001` in a separate output directory. Qualification manifests and subsets produce descriptive summaries only and can never set inference thresholds or overall qualification. This small timing exercise therefore does not consume production seeds.

The script contract separates preparation from execution. `prepare.R` refuses an existing output directory, verifies the isolated installed package, runs deterministic group-SD DGP checks for every group under negative, zero, and positive slope conditions, writes the immutable manifest and environment/source hashes, and records `prepared_not_launched`. It prints `REGISTRY_SHA256`; preserve that digest outside the prepared directory and pass it to the launcher. `run.py` requires that external seal and verifies every registered hash before launch. At most 16 workers run with BLAS/OpenMP thread caps, 120 seconds per case, and a 3,600-second campaign cap. It kills and waits for timed-out or interrupted worker process groups and retains explicit `not_started`, `launch_error`, `started`, `completed`, `error`, `timeout`, `campaign_timeout`, and `interrupted` states. Subset copies preserve the original registry byte-for-byte and contain the full byte-identical manifest; the subset receipt names planned indices. `worker.R` checks the external seal, artifact hashes, loaded library, and supervisor-planned index before fitting. It journals started/profiling/completed states atomically, retains diagnostics, and requires finite absolute Laplace-oracle discrepancy below `1e-6` for interval validity. A worker error is retained as an attempt; there are no silent retries.

The pinned artifacts include the exact helper, all harness scripts and this design file, native R/C++ source files, loaded `drmTMB` DLL, installed `DESCRIPTION`, `NAMESPACE`, metadata, `drmTMB.rdb`/`.rdx`, and R executable. `source-hashes.csv` includes the full manifest and binds the prepared run to SHA-256 digests. Launcher requires the independently recorded registry digest; worker and summary compare it again. Launcher, worker, and summary fail closed if registered artifacts change; worker confirms the loaded package and DLL paths are the pinned installation. For a subset directory, summary verifies the externally sealed registry byte-for-byte against the prepared source directory, checks that the prepared source manifest is registry-pinned, and checks the copied manifest hash against both source and subset receipt. Summary also checks result/supervisor identity and requires a zero-exit completed supervisor state for a valid interval. `sessionInfo.txt` records the runtime environment.

## Historical candidate decision thresholds

The current staged rule is specified in `staged-calibration-contract.md`. It uses 97.5% Monte Carlo confidence intervals for the qualifying operating characteristics at each look. At look one, exact binomial intervals for nominal 95% fitted-profile coverage across all 1,000 planned attempts per truth must be contained in `[0.925, 0.975]`; the null planned-denominator false-positive interval must be contained in `[0.025, 0.075]`; and the lower endpoint for valid-interval fraction must be at least 0.95. Invalid intervals and absent attempts count as noncoverage. Conditional coverage, attempted-process coverage, and conditional null false-positive rate remain descriptive. The finite-estimate t intervals for log-SD and relative `exp(a)` bias remain visible as diagnostics only: their coverage is unvalidated under skew, rare tails, and outcome-dependent missing estimates, so they do not enter acceptance. A result passing the staged rule qualifies only these interval-calibration and availability criteria under the declared DGP; it does not establish point-estimator recovery. No eligible current-source fitted-model calibration result is presently available.

If separately authorized after runtime estimation, look two adds 3,000 attempts per truth and analyzes the cumulative 4,000 per truth. Its Monte Carlo confidence intervals for qualifying operating characteristics also use 97.5% confidence. An all-pass result accepts these criteria, a failed qualifying gate stops, and ambiguity is inconclusive with no third look. Look-two seed identities are frozen in `stage-two-manifest.csv` (SHA-256 `8fd627ccb8a7f8689c56e629a5ff12e53405be1a508167216632bcf445652e96`) and reproducibly checked by `stage-two-seeds.R`. The prepare step pins the staged analyzer, seed producer, frozen CSV, and staged calibration contract in the source registry. It checks the CSV against the deterministic producer to within `1e-14` for numeric columns. The first-look summarizer invokes the staged decision only after result and supervisor identities are reconciled; it writes `staged-decision.rds`, metrics, gates, and attempt status counts. Only a complete production first-look `accept` sets the overall qualification flag. A staged `fail` is operational nonqualification, not proof that the statistical method is invalid. Qualification manifests, subsets, and incomplete campaigns keep every qualification gate false.

These margins are proposed and require independent inference review before any production interpretation. The six-seed pilot established feasibility only and does not set these tolerances. The existing source estimate is 9–14 seconds per seed on Totoro; 3,000 attempts with 16 workers plus profiling and serialization overhead are estimated at 45–60 minutes. No remote launch or fitting was performed while building this harness.

## Checks

`python3 tools/general-sd-regression/native-calibration/self-test.py` checks DGP truth identities, deterministic stage-two CSV generation and digest, staged-analyzer unit cases, harmless positive/error/timeout/launch-error workers, parent-SIGTERM cleanup and nonzero CLI exit, artifact mutation and result identity controls, stopped/interrupted denominator gates, qualification ineligibility, runner-style copied-subset manifest pinning and its negative controls, and the R summarizer against a handcrafted 3,000-row set with known 950/1,000 coverage and 50/1,000 null false positives. It verifies that the analyzer and descriptive summary use matching 97.5% coverage intervals and that only the staged accept can qualify. A separate null fixture checks conditional false positives against the planned denominator. It performs no fits.

## Bounded qualification procedure

Run on the host and installed-library capsule intended for the test, from the repository root. Choose two new output paths; preparation and subset creation refuse overwrite. Qualification uses master seed `2026101704`, is disjoint from pilot (`2026101702`) and production (`2026101703`), and cannot set qualification flags. The registry hashes both current source files and installed binary artifacts; it does not independently prove which source produced an installed binary. On Totoro, use the matching original Bernoulli source capsule and isolated library, retaining the source/build receipt that ties them together before preparation.

```sh
Rscript tools/general-sd-regression/native-calibration/prepare.R /fresh/path/sd-qualification --qualification | tee /fresh/path/sd-qualification-prepare.log
# Copy the printed REGISTRY_SHA256 into a separately retained record, outside the prepared directory.
python3 tools/general-sd-regression/native-calibration/run.py /fresh/path/sd-qualification \
  --indices 1,1001,2001 --subset-output /fresh/path/sd-qualification-subset \
  --workers 3 --case-timeout 120 --campaign-timeout 120 \
  --registry-sha256 <externally-recorded-digest>
Rscript tools/general-sd-regression/native-calibration/summarize.R \
  /fresh/path/sd-qualification-subset <externally-recorded-digest>
```

The estimate for these three attempts is 45–90 seconds including startup and profiling, using the prior 9–14 seconds per seed source estimate. This is a bounded pre-run, not evidence for the 3,000-fit campaign; the external registry digest and exact worker receipts must be retained for review.

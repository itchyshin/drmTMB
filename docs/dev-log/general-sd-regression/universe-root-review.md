# Required-universe scope review

Status: G0 remains open. Source shape and programme obligation are distinct.

The approved plan requires missing base plumbing across the frozen primitive
union and prohibits treating absent implementation as non-identifiability.
A source-constrained block rule is useful inventory evidence. It cannot by
itself structurally exclude an endpoint or provider combination.

In the current expansion, preserve rows for nu/zi/hu/zoi/coi/rho12 block targets
and mesh covariance mechanisms as unresolved or blocked base plumbing unless a
mathematical or explicit approved-scope argument excludes them. Do not use
`structural_inapplicable` solely because only mu/sigma or q1 mesh code exists.
A cross-endpoint block in a genuinely single-endpoint family is different:
there is no second endpoint, so that exact mechanism is inapplicable.

For multi-endpoint blocks, retain a finite canonical candidate member-set
universe over actual family endpoints, separately marking source-admitted
compositions and unresolved candidate compositions. Do not claim those
candidates are fitted or identifiable. Use the existing covariance mechanism
and admitted coefficient-set templates; arbitrary new kernel/provider pairs
remain outside the agreed programme. A disputed interpretation stays open in
the required ledger instead of disappearing through an exclusion label.

For q-generic mechanisms, retain a machine-readable symbolic q rule and finite
validation anchors. Missing q support on one provider/engine is a prerequisite,
not evidence that its covariance is structurally impossible.

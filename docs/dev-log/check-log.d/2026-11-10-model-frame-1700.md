# 2026-11-10 model.frame() for a drmTMB fit (#1700)

`stats::model.frame.default` returns `fit$model` when that component exists.
For a `drmTMB` fit that component is the TMB specification, not the rows used
to fit. `model.frame.drmTMB` now returns the stored location (`mu`) data frame
and its `terms` attribute. `fit$model` is not renamed or rebuilt.
`terms.drmTMB` and `model.matrix.drmTMB` use that same frame.
`stats::model.matrix.default` evaluates `environment(object)` when `data` is
missing, which a fit list cannot supply, so the matrix method is required.

A bivariate fit stores `mu1` and `mu2`, not `mu`. Combining those frames needs
a row alignment and one `terms` attribute, so `model.frame()` stops and names
the stored frames. Scale and shape columns are not bound into the location
frame. An `engine = "julia"` fit is class `drmTMB_julia` and does not store a
location model frame; `model.frame()` stops instead of returning
`fit$model`.

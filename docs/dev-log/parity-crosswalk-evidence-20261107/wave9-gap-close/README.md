## 1. Which two groups, and why

Source: `fuzz-gap-map/` (196 cells where R fits and Julia does not, 51 groups). Skipped: groups caused only by the keyword MethodError (another lane), and the missing-data refusal groups (report only).

**Group A. A bare structured `(1 + x | g)` block with no `sd()` formula.**
`animal`, `relmat`, `phylo`, `spatial` with Gaussian, Poisson, NegBinomial2, Gamma and Binomial (logit). In drmTMB 0.8.1 this is the independent two-SD model (labelled `(1 + x | p | g)`: the correlated one). Julia already fit the same model when the user wrote `sd(g, kind, coef(.)) ~ 1` for both coefficients, so the gap was a refusal at the entry point, not missing maths. Closes 21 cells in the gap map (including 4 bare Gamma cells).
Julia refusal texts before (verbatim, from `results/base_julia_before.txt`):
- `ArgumentError: drm: relmat(1 + x1 | g) is not implemented on the univariate routes; only the intercept form is admitted on this route` (also the `spatial(...)` twin)
- `ArgumentError: drm: animal(1 + x1 | g) is not implemented on the univariate routes; only the intercept form is generally available, and a slope-only or independent intercept-and-slope animal term is available only on an explicitly supported family-specific SD route`
- `ArgumentError: drm: phylo(1 + x1 | g) is not implemented on this route - only phylo(1 | g) (intercept) is here. The two-SD phylogenetic random intercept + slope phylo(1 + x | g) is implemented for the Gaussian mean only ...`

**Group B. Gamma `phylo(1 + x | g)` and `spatial(1 + x | g)` with one SD formula per coefficient** (independent and labelled for phylo; independent for spatial, since drmTMB refuses the labelled spatial form).
Julia refusal text before: `ArgumentError: Gamma structured SD regression requires exactly one random-effect SD formula.` Closes 6 cells (4 phylo, 2 spatial); the bare Gamma phylo and spatial cells are counted in Group A.

Why these two: they are bounded. Group A reuses the existing two-SD routes and only completes the default SD formulas. Group B reuses the Gamma two-field Laplace engine and the phylo/spatial kernel helper that Poisson/NB2 already use. The remaining top groups needed new likelihoods (Beta structured SD, Tweedie structured, censored) or were the keyword MethodError lane.

R behaviour reproduced: every cell above fits in R (`fuzz-gap-map/gap_map.tsv`, r_outcome FITS); R loglik values are in `results/r_all.tsv`.

## 2. What was built (Julia repo)

## 3. R-vs-Julia agreement study

One dataset per shape, 11 seeds each (0 to 10), 11 shapes = 121 paired fits, ML at the optimum. Data are generated by `scripts/gen_w9.jl` (seeded; the 204 CSVs are not committed, regenerate with that script). R runs on Totoro (`scripts/agree.R`), Julia on the Mac and Totoro (`scripts/agree.jl`, `scripts/agree_defs.jl`), run separately.

Thresholds, written before any result was read (top of `scripts/analyse.py`):
- T1 |dLL| <= 1e-4.
- T2 mean and sigma coefficients: flag if |d| > 5e-3 or |d| / SE_R > 0.02.
- T3 SD and correlation parameters (log-SD, SD coefficients, atanh rho): flag if |d| > 0.02.
- T4 any non-finite SE in either engine.

Julia is at the higher optimum in B2 seed 2 (by 0.457), R is at the higher optimum in B5 seeds 9 and 10 (by 0.458 and 1.41). So neither engine is wrong about the objective; the sd-z formula with a coordinate SD has a second mode and the two start rules land on different ones. This is not closed: the Julia fit can sit at the lower mode, and I did not add multi-start.
- T6 (information only): 2 of 121 fits have an SE ratio outside [0.9, 1.1] (B2 seed 2, B5 seed 10), both of them seeds in the different-mode set above.

## 4. The nine unexplained both-fit loglik disagreements

From `fuzz-gap-map/loglik_disagreements.tsv`: Tweedie ordinary (3 cells) and slope-only (3 cells), Gamma spatial q = 1 (3 cells).

**Tweedie (6 cells): same model, different integral.** R's TMB fit uses the Laplace approximation to the random-effect integral. Julia integrates each group with 21-node adaptive Gauss-Hermite quadrature, which is close to exact. `disagreements/tw2_result.tsv` evaluates all four combinations at each engine's own parameters:

| cell | R reported | Julia reported | Laplace at R's theta | Laplace at Julia's theta | Quadrature at R's theta | Quadrature at Julia's theta |
|---|---|---|---|---|---|---|
| ord_none | -766.56678 | -766.64768 | -766.56678 | -766.56688 | -766.64778 | -766.64768 |
| ord_z | -766.53566 | -766.61666 | -766.53566 | -766.53576 | -766.61676 | -766.61666 |
| slope_none | -780.89644 | -780.96428 | -780.89644 | -780.89689 | -780.96473 | -780.96428 |
| slope_z | -777.07208 | -777.10234 | -777.07208 | -777.07217 | -777.10243 | -777.10234 |

Each engine reproduces its own number, and the Laplace value is higher than the quadrature value at the same parameters by 0.03 to 0.08. Both are at their own objective's optimum (the other engine's parameters change that objective by about 1e-3 or less). Verdict: the same model; R is not "better", it is a different approximation. The Laplace approximation overstates the likelihood here, so Julia's number is the closer one to the true marginal likelihood. Practical consequence: Tweedie logLik will not match drmTMB to better than about 0.1 in these shapes, and AIC comparisons across engines are invalid. Not a bug in either engine.

**Gamma spatial q = 1 (3 cells): different kernel, not a different optimum.** Julia's spatial kernel used the mean pairwise distance and a 1e-8 nugget; drmTMB uses exp(-d / median distance) plus 1e-6 on the diagonal. `disagreements/gs_result.txt`: with Julia given R's kernel, the loglik matches R to 1e-10 (sd-z: R -404.2755360722, Julia with R's kernel -404.27553607216; Julia on its own coordinates kernel -404.33785). So the two engines were fitting different models. This is a modelling choice, not a numerical error, and I have not changed Julia's default kernel (it would move every existing spatial fit). The Group A and B spatial cells above use the shared helper `_structured_q2_kernel`, which uses R's kernel, which is why they agree to 1e-9. The q = 1 Gamma spatial route that still uses the older kernel is the one place the two kernels coexist in Julia. Recommend deciding whether to move that route to the shared kernel.

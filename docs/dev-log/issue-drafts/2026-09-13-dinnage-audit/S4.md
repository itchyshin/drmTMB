TITLE: [Dinnage audit S4] vcov(fit, type = "robust") silently returns the model-based covariance
LABELS: audit-dinnage, bug, major
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row S4; severity major).
Supporting working: none cited beyond the reproduction in §4

## What Russell found
`vcov(fit, type = "robust")` and `vcov(fit, robust = TRUE)` both `all.equal()` the plain model-based
`vcov(fit)`, with no warning and no message. There is no `estfun()` method, so `sandwich::vcovHC(fit)`
errors ("no terms component nor attribute") rather than filling the gap. On Student-t(3) data the
model-based SE is 3.0x too small with Wald coverage 0.572 — the classic quasi-ML problem — so a user
who reflexively asks for robust SEs on misspecified data gets model-based ones back, silently, and may
report them as robust.

## Where (at 945da24f)
`R/methods.R:2331` (`vcov.drmTMB`).

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `vcov.drmTMB` is at `R/methods.R:2331`, signature `function(object, ...)` — it accepts no
`type` or `robust` argument at all; any such argument passed by a caller lands silently in the unused
`...` and is discarded. The function body (`R/methods.R:2331-2360+`) always builds `out` from
`drm_sdreport_cov_coefficients(object)` (the model-based sdreport covariance) with no branch on `...`.
`grep -n "estfun\." R/*.R` returns no matches, confirming no `estfun()` method exists anywhere in the
package. `git log -p 945da24f..HEAD -- R/methods.R` shows two small diffs touching `vcov.drmTMB`'s body
(unrelated to a `type=`/`robust=` argument — the signature is still `function(object, ...)` after
both), so the gap is unchanged since the audit. No existing-issue match found (checked "vcov robust",
"estfun", "sandwich" in open-issues.json).

## Proposed fix (Russell's, if stated)
Cheap to fix: an error or a warning when `type = "robust"` / `robust = TRUE` is requested but not
implemented, rather than silent substitution. A full fix would add a sandwich/robust covariance
estimator and an `estfun.drmTMB()` method for `sandwich` compatibility.

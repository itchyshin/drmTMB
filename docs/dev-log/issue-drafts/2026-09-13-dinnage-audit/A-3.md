TITLE: [Dinnage audit A-3] `is_converged()` stays a plain boolean, so `multi_start` can clear it on a likelihood with no maximum
LABELS: audit-dinnage, bug, moderate
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row A-3; severity moderate).
Supporting working: a genuinely unbounded singleton likelihood fitted at several `multi_start` values.

## What Russell found
`is_converged()` returned TRUE on 28-35.5% of fits at the default `multi_start` and 95-95.5% at
`multi_start = 25`, at an identical logLik of -10.07942705 with coefficients differing by up to 50.1
across starts -- i.e. `multi_start` increases the *rate* at which a flag reads TRUE on a likelihood that
has no maximum. Strongly mitigated: `check_drm()` is fully green on 0.0% of these draws, SEs are finite
on 0%, and a "singular convergence (7)" warning fires on 100%. `gamlss` on the same data converges and
prints starred coefficients that are fully publishable and entirely meaningless; drmTMB refuses to hand
any of that over. Russell's ask: a three-valued `is_converged()`, or stop `multi_start` clearing a flag
it did not earn.

## Where (at 945da24f)
`R/drmTMB.R` (`is_converged`, multi-start loop), per Appendix A.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `is_converged.drmTMB()` (`R/check.R:225-256`) is unchanged in substance: it returns
`optimizer_ok <- identical(as.integer(object$opt$convergence), 0L) && isTRUE(all(is.finite(objective_values)))`
-- a plain logical, with no distinction for degenerate/no-maximum geometry, and no adjustment for
`multi_start`. `multi_start` default is unchanged at `R/control.R:182` (`multi_start = 1L`). `git log
--oneline 945da24f..HEAD -- R/check.R` shows no commit touching `is_converged.drmTMB` or its return type.
No existing-issue match: `gh issue list --search "is_converged"` and `--search "multi_start"` return
issues about serial execution and parallelization (#1248, #1254) and performance, none about the flag's
information content on a degenerate likelihood.

## Proposed fix (Russell's, if stated)
"A three-valued `is_converged()`, or stop `multi_start` clearing a flag it did not earn." Russell notes
everything else about this behaviour (the warning, the green-board 0%) is right, so the narrowest fix is
scoped to the flag itself, not the fitting mechanism.

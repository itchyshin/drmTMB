TITLE: [Dinnage audit A-4] `meta_V()` is positional, `relmat()` is name-keyed, and only the second says so
LABELS: audit-dinnage, documentation, moderate
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row A-4; severity moderate).
Supporting working: permuted-row and foreign-dimnames matrices supplied to each marker.

## What Russell found
`meta_V(V = matrix)` aligns strictly by row position and ignores `dimnames` entirely; `relmat(K)` is
strictly name-keyed and enforces it with two of the package's best error messages. A `V` with entirely
foreign dimnames fits with an identical logLik and no warning; permuting the data rows while leaving `V`
alone moves the moderator coefficient 0.4379 -> 0.3633 (17%) with `is_converged() = TRUE`. **Refuted as a
defect**: `metafor::rma.mv` on the same data is also positional and also silent about foreign dimnames --
positional `V` is the meta-analysis convention, and on the correctly aligned fit drmTMB and `rma.mv` agree
to six decimals. What remains is that `?meta_V` never says "position" while `?relmat` is explicit about
being name-keyed, so a user cannot learn the two markers follow opposite conventions from the docs alone.

## Where (at 945da24f)
`man/meta_V.Rd`.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `man/meta_V.Rd` (generated from `R/formula-markers.R`) still documents only `V`'s accepted
shapes ("A column name, vector, diagonal matrix, block-diagonal matrix, or full covariance matrix
...") with no mention of row order or `dimnames`. `R/drmTMB.R` contains no positional-vs-name-keyed
guard or message for `meta_V()` (the ~15 `meta_V` call sites found are all "not implemented for
{family}" family-gating errors, none about alignment). `relmat()`'s documented name-keyed convention is
unaffected. `git log --oneline 945da24f..HEAD -- R/formula-markers.R man/meta_V.Rd` shows no relevant
commit. No existing-issue match: `gh issue list --search "meta_V"` returns issues about phylo/relmat
twin-parity tracking, none about this documentation gap.

## Proposed fix (Russell's, if stated)
"`?meta_V` is two sentences and never says 'position'. One word, so that a user can learn the two markers
follow opposite conventions." Not a defect relative to the incumbent (`metafor` shares the convention);
this is purely a documentation gap.

Correction to the posting-time status note above (2026-09-13, same day).

The "resolved by correcting the documentation" statement was wrong and that commit has been reverted (`9ed334009` on `claude/audit-dinnage-wave2a-20260913`). The independent Fisher review found that `src/drmTMB.cpp:86-90` and `docs/design/172-phylo-penalized-map.md:44-53` both describe the `-log(sd)` term as the log-Jacobian of the documented exponential PC prior, so the documented calibration `P(sd > sd_u) = sd_alpha` is true of the prior itself. What Russell measured (an interior mode at `1/rate`, pulling the SD away from zero rather than toward it) is the maximum-a-posteriori estimate in `log(sd)` not being parameterisation-invariant.

This issue therefore stays open as a design decision: penalise on the SD scale so the MAP honours the documented shrinkage toward zero, or keep the log-scale MAP and document that its mode sits at `1/rate`. No code or documentation change from the audit response is currently applied for S3.

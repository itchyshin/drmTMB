TITLE: [Dinnage audit Mi-12] `R/aghq-coxreid.R`'s two near-duplicate optimiser branches diverge: `maxit` set in one, not the other; convergence unchecked in both
LABELS: audit-dinnage, bug, minor
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row Mi-12; severity minor).
Supporting working: line-by-line comparison of the two `optim()` call sites in the same file.

## What Russell found
`R/aghq-coxreid.R` contains a near-duplicate that diverged forty lines apart in the same file: the
`aghq_cr` inner `optim()` sets no `maxit` and never checks `convergence`; the `aghq` branch forty lines
below sets `maxit = 400`.

## Where (at 945da24f)
`R/aghq-coxreid.R`.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `drm_o3_cr_negll()`'s inner call (`R/aghq-coxreid.R:113`) is `stats::optim(psi_start, fpsi,
method = "BFGS", control = list(reltol = 1e-8))` -- no `maxit`, and the returned `o$convergence` is never
inspected (only `o$value` and `o$par` are used). The `aghq` branch's call (`R/aghq-coxreid.R:154`, 41 lines
below) is `stats::optim(c(psi0, log(0.7)), obj, method = "BFGS", control = list(reltol = 1e-8, maxit =
400))` -- `maxit = 400` is set, but its `o$convergence` is also never checked afterward. Both branches thus
share the "convergence unchecked" defect; only the `maxit` setting differs between them, exactly as
reported. `git log --oneline 945da24f..HEAD -- R/aghq-coxreid.R` shows no commit unifying the two calls.
No existing-issue match: #934 ("Gate 2 -- audit drmTMB's OWN AGHQ: integrator correct vs estimator
established") is a related but distinct concern (whether the AGHQ *estimator* is statistically
established), not this specific code-duplication/convergence-checking defect. `gh issue list --search
"aghq-coxreid"` returns only #934.

## Proposed fix (Russell's, if stated)
"Small" -- unify the two `optim()` calls' control arguments and add a convergence check to both.

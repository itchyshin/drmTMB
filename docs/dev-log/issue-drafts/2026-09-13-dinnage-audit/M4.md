TITLE: [Dinnage audit M4] simulate() leaks the internal missing-response sentinel for 12 of 13 families
LABELS: audit-dinnage, bug, major
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row M4; severity major).
Supporting working: none cited beyond the reproduction in §4

## What Russell found
`miss_control(response = "include")` keeps rows with a missing response by substituting an internal
sentinel and excluding them from the likelihood; the package's own error message states the invariant
that this sentinel must never reach the user as data. `residuals()` honours it. `simulate()` honours
it in exactly one branch (`beta_binomial`, hand-rolled) and returns the raw sentinel (`0` for
gaussian/student/skew-normal/tweedie/zero-one-beta, `1` for lognormal/gamma) at masked rows for the
other twelve families. The helper that would fix this generically already exists
(`R/missing-data.R:546-565`) but is not called from `simulate()`. This matters for the canonical
`DHARMa::createDHARMa()` posterior-predictive workflow, which pairs `simulate()` against the stored
response — masked rows would compare genuine draws against a constant, producing a spurious
misspecification signal driven by rows carrying no data (reasoned, not run, by Russell's team).
`man/simulate.drmTMB.Rd` does not mention missing responses.

## Where (at 945da24f)
`R/methods.R:3235-3241` (the one correct beta_binomial branch), `R/missing-data.R:546-565` (the
unused generic helper), `man/simulate.drmTMB.Rd`.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `simulate.drmTMB()` now starts at `R/methods.R:2982`; the only masking assignment in its
whole body (through ~line 3578) is `sims[!object$missing_data$observed_y, ] <- NA_integer_` at
`R/methods.R:3256` (drifted ~20 lines from the report's :3235-3241, same beta_binomial branch,
unchanged logic). No other family branch in `simulate.drmTMB` performs any masking. By contrast,
`R/methods.R` shows over a dozen `drm_mask_missing_response_values(...)` call sites (from ~3750
onward) inside `residuals.drmTMB`, confirming residuals continue to honour the invariant that
simulate still does not. No existing-issue match found.

## Proposed fix (Russell's, if stated)
Add one masking pass on the assembled simulation frame in a wrapper (reusing the existing
`R/missing-data.R:546-565` helper) rather than the current per-family hand-rolling, plus a test
looping over families asserting `all(is.na(simulate(fit)[!observed_y, ]))`. Promote to Critical if
the same sentinel is confirmed to reach `centile_chart()`, `worm_plot()`, `prediction_grid()` or the
`adequacy` layer (unread in this evaluation, per §9).

TITLE: [Dinnage audit M2] sigma()/predict()/residuals() report the unclamped scale, not the fitted one
LABELS: audit-dinnage, bug, major
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row M2; severity major).
Supporting working: none cited beyond the reproduction in §4

## What Russell found
When the `log(sigma)` soft-clamp is active (see C1), the likelihood evaluates the *clamped* scale,
but `sigma()`, `predict()` and `residuals()` all report the raw, *unclamped* linear predictor: on a
fit where the clamp engages, `sigma(fit)` differed from the clamped value the likelihood used by up
to 14.71x on 399/400 observations, and `sd(residuals(fit, type = "pearson"))` came out at 2.509
(should be ~1) — a user reading the package's own residual diagnostics would see 2.5x the correct
spread and wrongly conclude gross misspecification. Recomputing the log-likelihood by hand under
`sigma(fit)` loses 752 nats versus the value the fit actually reports. This is documented nowhere.
It is genuinely separate from C1 (present whenever the clamp is active at all, not only in C1's
small-scale regime) but was demoted from Critical to Major because its silent form is a strict
subset of C1's.

## Where (at 945da24f)
`R/drmTMB.R:22335` (`drm_softclamp_log_sd`, the function that should be but is not called),
`R/methods.R` (`sigma.drmTMB` / `predict.drmTMB` / residual-scale extraction).

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `drm_softclamp_log_sd()` is now defined at `R/drmTMB.R:22941` and called only at two
random-effect-SD sites in `R/drmTMB.R` (~22967, ~22991) — a
`grep -n "drm_softclamp_log_sd\|softclamp" R/*.R` shows zero call sites in `R/methods.R`.
`sigma.drmTMB` (`R/methods.R:4035`) dispatches to `predict(object, dpar = "sigma")` for every family,
which builds the reported scale from `exp(eta)` on the raw linear predictor — no soft-clamp is
applied anywhere in that path. `git log --oneline 945da24f..HEAD -- R/methods.R` was not inspected
commit-by-commit for this specific line, but the absence of any `softclamp` reference in the file
today is sufficient to confirm the accessor path is unchanged. No existing-issue match found.

## Proposed fix (Russell's, if stated)
Route the residual-scale extraction (and `sigma()`/`predict()`) through `drm_softclamp_log_sd()`,
exactly as the two random-effect-SD call sites already do — or report both the raw and clamped
values and label which is which. Estimated 1 line.

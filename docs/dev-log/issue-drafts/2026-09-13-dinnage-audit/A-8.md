TITLE: [Dinnage audit A-8] `dropped_rows` counts rows lost to MCAR missingness but not groups; six of forty individuals can vanish unmentioned
LABELS: audit-dinnage, enhancement, moderate
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row A-8; severity moderate).
Supporting working: 5/15/30% MCAR sweeps on a random-effect design.

## What Russell found
Rows yes, groups no. `nobs()` and `df.residual()` are correct and `check_drm()` carries `dropped_rows
nobs=272; dropped=48` -- a reasonable contract. But when six of forty individuals lose *every* row, the
note still reports only rows and names no groups. In a model with a random-effect scale submodel, the
number of surviving groups is the entire information content of that submodel. Credit: at 30% MCAR a
`random_effect_sd_boundary` warning fires unprompted, and `interval_reliability_scope` tells the user to
read `conf.status` before quoting an interval.

## Where (at 945da24f)
`R/check.R:826` (`check_dropped_rows`).

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `check_dropped_rows()` is now at `R/check.R:1180-1200` (line drifted, logic unchanged): it reads
`keep <- object$model$keep`, computes `dropped <- sum(!keep)`, and returns a row whose `value` is
`"nobs=<n>; dropped=<k>"` -- a row count only. There is no reference anywhere in the function (or in the
neighbouring `check_random_effect_replication()` / `check_random_effect_design()` functions, which do
compute group-level replication but are not consulted here) to how many *groups* lost every row. `git log
--oneline 945da24f..HEAD -- R/check.R` shows no commit touching `check_dropped_rows`. No existing-issue
match: `gh issue list --search "dropped_rows"` returns nothing on point.

## Proposed fix (Russell's, if stated)
"Count groups lost as well as rows, in the same note."

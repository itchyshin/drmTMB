TITLE: [Dinnage audit Mi-16] `sigma()` returns an n-vector, so `insight::get_sigma()` collapses a 0.16-3.00 range to one number
LABELS: audit-dinnage, documentation, minor
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row Mi-16; severity minor).

## What Russell found
`sigma()` returns an n-vector (one value per observation, when a `sigma ~ x` submodel is fitted), so
generic tooling built against `stats::sigma()`'s scalar contract (e.g. `insight::get_sigma()`) collapses a
0.16-3.00 fitted range to a single number (0.7685 in Russell's example) rather than erroring or
representing the per-observation heterogeneity.

## Where (at 945da24f)
`R/methods.R` (`sigma.drmTMB`).

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `sigma.drmTMB()` (`R/methods.R:4035-4071`) returns `predict(object, dpar = "sigma")` for
`gaussian`, `student`, `skew_normal`, `lognormal`, `gamma`, `tweedie`, `beta`, `zero_one_beta`,
`beta_binomial`, `nbinom2`, `truncated_nbinom2`, `hurdle_nbinom2`, `zi_nbinom2` -- a length-`nobs(object)`
vector whenever the `sigma` submodel has covariates, not a scalar. No length-1 summary or documented
caveat exists at this call site for consumers (like `insight::get_sigma()`) that expect the base
`stats::sigma()` scalar contract. `git log --oneline 945da24f..HEAD -- R/methods.R` (filtered to
`sigma.drmTMB`) shows no commit adding a scalar-summary path or interface note. No existing-issue match:
`gh issue list --search "get_sigma"` and `--search "sigma() vector"` return nothing.

## Proposed fix (Russell's, if stated)
"Interface note only" -- Russell frames this as a documentation gap rather than asking for a scalar
`sigma()`, since the n-vector is the more informative return value for a heteroscedastic model.

## Acceptance
- [ ] `?sigma.drmTMB` states that the return value is an n-vector whenever the `sigma` submodel has
      covariates, and that generic tooling assuming a scalar (e.g. `insight::get_sigma()`) will summarize
      it, not preserve it

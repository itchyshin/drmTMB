TITLE: [Dinnage audit S7] Default single start lands >= 1 AIC worse on 18.3% of joint sigma+zi fits
LABELS: audit-dinnage, enhancement, moderate
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row S7; severity moderate).
Supporting working: `sigma ~ x` + `zi ~ x` fits against `glmmTMB` on identical draws at n = 400, 673
replicates pooled.

## What Russell found
Fitting a scale submodel and a zero-inflation submodel jointly — "the shape a user is most likely to
write next" — is a two-basin objective (median |ΔlogLik| 2e-10 to 8e-10 where drmTMB and `glmmTMB`
agree). At the default single start, drmTMB lands >= 1 AIC worse than `glmmTMB` on 18.3% of replicates
at n = 400 (median penalty 15.0 AIC, max 38.2; pooled 69/673 = 10.3%), and `is_converged()` is TRUE on
100% of the bad replicates — `check_drm()` does not warn more on the bad replicates than the good ones.
`multi_start = 4L` on the same draws recovers 49/55 (89%) and never lowered the log-likelihood across
673 replicates. The finding is about the *default*, not a missing feature — `multi_start` exists and
works.

## Where (at 945da24f)
`R/drmTMB.R` (`drm_control` default), `man/drm_control.Rd`.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `drm_control()` is now defined in `R/control.R` (not `R/drmTMB.R` — the function moved files
since the audit), with `multi_start = 1L` still the default at `R/control.R:182`. The default is
consumed at `R/drmTMB.R:851` (`n_start <- if (is.null(control$multi_start)) 1L else control$multi_start`)
inside `drm_optimize_with_preset_retry()`. `man/drm_control.Rd:128-132` documents `multi_start` ("default
1") and what raising it does, but says nothing about jointly-specified submodels being more prone to
local optima or needing a higher default/explicit recommendation. `git log --oneline 945da24f..HEAD --
R/control.R` shows commits touching `multi_start` handling for the Julia engine rejection path
(`89bfd210a`) and the `start=` contract (`0635774bd`), none raising the default or adding a
joint-submodel warning. No existing-issue match found (checked "multi_start", "joint sigma"/"zi ~ x" in
open-issues.json — #1248 "multi_start walks independent starts in a serial for-loop" is about
parallelising existing starts, not the default value or joint-submodel risk, so not a match).

## Proposed fix (Russell's, if stated)
"Raise the default for jointly specified submodels, or say in `?drm_control` that this shape needs it."

TITLE: [Dinnage audit A-5] No `check_drm()` row is sensitive to response-distribution damage; the board gets no cleaner while the fit gets worse
LABELS: audit-dinnage, enhancement, moderate
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row A-5; severity moderate).
Supporting working: a `-9999`-style sentinel swept from -1 to -99 through a Gaussian response.

## What Russell found
At sentinel -5 the **scale** coefficient attenuates from 0.43 to 0.133 (67.6%, seed-stable across eight
seeds) while the **mean** model stays 0.7 SE from truth and entirely publishable -- the mean model
outlives the distributional model, the opposite of the direction a user's intuition scans. Demoted from a
false result to a coverage gap: `gamlss` returns the identical answer on the identical corrupted frame.
`check_drm()` has no row that would notice the response itself is damaged: `residuals()` on that fit puts
64 of 400 rows beyond |3|, but nothing on the diagnostic board surfaces it.

## Where (at 945da24f)
`R/check.R` (no such row exists).

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. The current `check_drm()` row set (`R/check.R`, ~34 `check_*` functions covering optimizer
convergence, gradient, Hessian, SE finiteness/inflation, dropped rows, clamp status, boundary values,
scale-phylo identifiability, and family-specific `nu` diagnostics) contains no row that inspects response
residual magnitude or a comparable response-side sentinel/outlier signal -- confirmed by name-scanning
every `check_*` function currently defined in `R/check.R`. `git log --oneline 945da24f..HEAD -- R/check.R`
shows commits touching existing rows (clamp, hessian) but none adding a response-damage row. No existing-
issue match: `gh issue list --search "check_drm"` returns issues about specific existing rows
(`hessian_conditioning`, #1251) and capability twins, none proposing a response-sentinel row.

## Proposed fix (Russell's, if stated)
"A `check_drm()` row sensitive to response-distribution pathology would cost little, and the information
it needs is already computed" (residuals). Not a defect in existing behaviour -- damage to the data, not
a bug -- but a coverage gap on the diagnostic board.

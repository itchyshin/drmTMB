TITLE: [Dinnage audit A-6] `skew_normal()` with `nu ~ x` prints an unqualified Wald SE at a singular information matrix; type-I 0.236
LABELS: audit-dinnage, enhancement, moderate
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row A-6; severity moderate).
Supporting working: type-I error simulation at the Gaussian null (nu = 0), compared against `gamlss`'s `SN1()`.

## What Russell found
Wald type-I error is 0.236-0.238 on Gaussian truth (0.32-0.37 contaminated; 0.126/0.217 at alpha = 0.01,
so not a marginal-tail artefact), with 100% convergence, finite SEs, and `attr(ok)` TRUE on ~70% of fits.
The geometry is the family's (the information matrix is genuinely singular at alpha = 0) and is not in
dispute -- `gamlss`'s `SN1()` on the same data converges only 58.7% of the time and returns a non-finite
`nu`-slope SE in 21.3%. What is drmTMB's alone: an unqualified Wald standard error printed where the
geometry does not support one. The proposed profile-likelihood fix only half works (0.26 -> 0.093, still
~1.9x nominal).

## Where (at 945da24f)
`man/skew_normal.Rd`, `R/check.R`.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `check_skew_normal_nu()` (`R/check.R:1425-1461`) checks only that fitted `nu` values are finite
and flags (`note`) when `max(abs(nu)) > 10` -- it has no check of the information-matrix condition near
`nu = 0` (the singular-geometry boundary Russell's finding targets) and issues no warning about Wald SE
reliability there. `man/skew_normal.Rd` (checked for "singular", "Wald", "type-I": no matches) does not
warn that a Wald SE on `nu ~ x` near the Gaussian null is unreliable. `git log --oneline 945da24f..HEAD --
R/check.R man/skew_normal.Rd` shows no commit adding such a guard. No existing-issue match: `gh issue list
--search "skew_normal"` returns REs-support / family-doc issues (e.g. #1230, already a known overlap for a
different skew-normal contradiction) but none about Wald-SE calibration near `nu = 0`.

## Proposed fix (Russell's, if stated)
"A warning in `?skew_normal` plus a `check_drm()` row. Do not promise the profile fixes it; measured, it
does not." A likelihood-ratio-based caveat, not a claimed repair.

TITLE: [Dinnage audit S1] fitted_distribution()$p()/$d() collapse to length 1 on a scalar y for atom families
LABELS: audit-dinnage, bug, major
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row S1; severity major).
Supporting working: none cited beyond the reproduction in §4

## What Russell found
`?exceedance` documents `threshold` as "a single value (recycled across rows) or one value per row",
so `fitted_distribution(fit)$p(0)` should recycle a scalar across all `n` rows. It does for
`poisson`/`nbinom2` (`length(p(0)) == 1500`), but for `zi_poisson`, `zi_nbinom2`, `hurdle_nbinom2` and
`truncated_nbinom2` a scalar call returns length 1 — exactly row 1's value — while `$q()` recycles
correctly in every family. Running `?exceedance`'s own documented recipe verbatim disagrees with
`exceedance()` by up to 0.689 (`hurdle_nbinom2`). Scoped narrowly: `exceedance()` itself is calibrated
(type-I 0.048, coverage 0.950); only the documented scalar call on `fitted_distribution()` is wrong.

## Where (at 945da24f)
`R/family-dpq.R:1167` (`fitted_distribution`), `man/exceedance.Rd`.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `fitted_distribution.drmTMB()` is now at `R/family-dpq.R:1173`, and each atom family's `$d()`
and `$p()` closure wraps its computation in `ifelse(<test on y>, ...)`, e.g. `zi_poisson`
(`R/family-dpq.R:859-878`): `p = function(y, params) { ...; ifelse(y < 0, 0, zi + (1 - zi) *
stats::ppois(y, lambda = params$mu)) }`. `ifelse()`'s result length follows its `test` argument's
length, not its `yes`/`no` branches' — so a scalar `y` (`test = y < 0`, length 1) truncates the
length-`n` `zi + (1 - zi) * ppois(...)` computation down to length 1, discarding rows 2..n. The same
pattern recurs in `truncated_nbinom2` (`d()`/`p()` at lines 955/964, `ifelse(y < 1, ...)`),
`hurdle_nbinom2` (lines 1001/1017, `ifelse(y == 0, ...)` / `ifelse(y < 0, ...)`), and `zi_nbinom2`
(lines 1051/1057, same shape as `zi_poisson`). `poisson`/`nbinom2` (`R/family-dpq.R:900-919`) use
`stats::dpois`/`stats::ppois`/`stats::dnbinom`/`stats::pnbinom` directly with no `ifelse()` wrapper, so
R's ordinary vector recycling handles a scalar `y` correctly — consistent with the report's length-1500
vs length-1 split. `git log --oneline 945da24f..HEAD -- R/family-dpq.R` returns no commits, so the file
is untouched since the audit. No existing-issue match found (checked `p()`, `exceedance`, `recycl` in
open-issues.json).

## Proposed fix (Russell's, if stated)
Not stated beyond "small". Replace each `ifelse(<test>, a, b)` with `dplyr::if_else`-free vectorised
logic that recycles on the full parameter length first (e.g. compute at length `nrow(params)` by
recycling `y` explicitly with `rep_len(y, nrow(params))` before the `ifelse()`, or use
`pmax`/`pmin`-style arithmetic masking instead of `ifelse()`).

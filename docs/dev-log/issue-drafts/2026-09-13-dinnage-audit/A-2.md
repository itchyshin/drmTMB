TITLE: [Dinnage audit A-2] `miss_control(predictor = "fail")` does not fail, and its own help page disagrees with itself
LABELS: audit-dinnage, bug, moderate
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row A-2; severity moderate).
Supporting working: none cited beyond the repro (40 of 400 rows with an `NA` predictor).

## What Russell found
`miss_control(predictor = "fail")` is documented as the defensive default that "errors on missing
predictors." Fitting with 40 of 400 rows carrying `NA` in a predictor produced no error: `nobs = 360`,
zero conditions signalled, and output byte-identical to leaving `missing` unset. `?miss_control` itself
disagrees across two sections — Arguments says `"fail"` errors, Description says the default "keeps the
existing complete-case behaviour."

## Where (at 945da24f)
`R/missing-data.R` (`miss_control()` and its documentation), `man/miss_control.Rd`.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `predictor` still defaults to `"fail"` (`R/missing-data.R:47`), and the only place the value
`"fail"` is inspected is `R/drmTMB.R:2818` (`default_predictor <- identical(missing_control$predictor,
"fail")`), used solely to gate the REML missing-engine check — not to raise an error. Every model-fitting
path drops missing-predictor rows unconditionally via `stats::complete.cases()` (e.g.
`R/drmTMB.R:4095`, `:4737`, `:5062`, `:5374`, `:6013`, `:6934`, `:7240`, `:7808`, `:8163`), with no branch
that checks `predictor == "fail"` and aborts. `man/miss_control.Rd` still states `"fail" errors on
missing predictors` in Arguments while Description still calls this "the existing complete-case
behaviour" — the self-contradiction is unchanged.

## Proposed fix (Russell's, if stated)
Bounded by `check_drm()`'s `dropped_rows` row correctly reporting `nobs`/`dropped`, which is what a user
should rely on until this is fixed. Russell's ask: "Make `"fail"` fail, or say it does not."

TITLE: [Dinnage audit S3] drm_phylo_penalty() fits a Gamma(2, rate), not the exponential/PC prior the page promises
LABELS: audit-dinnage, bug, major
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row S3; severity major).
Supporting working: 1,125 fits regressing the reported penalty on candidate closed forms, confirmed on
450 further penalised fits and 500 paired penalised/unpenalised fits under a true null.

## What Russell found
`?drm_phylo_penalty` promises an exponential/PC prior on each phylogenetic SD calibrated so that
`P(sd > sd_u) = sd_alpha`. Measured against the actual fitted penalty, the exponential/PC form is off
by 3.257, while a `Gamma(2, rate)` form agrees to 8.88e-16. The documented calibration is out by 5.6x
at alpha = 0.01 and 4x at alpha = 0.05, and the direction of regularisation is reversed: under a true
null the penalty pushes `sd_phylo` away from zero (implied prior mode `1/rate` = 0.3338 at defaults),
not toward it — the penalised estimate exceeded the unpenalised one in 496 of 500 paired fits.

## Where (at 945da24f)
`R/penalty.R:54` (`drm_phylo_penalty`, builds the documented rate), `man/drm_phylo_penalty.Rd`.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `drm_phylo_penalty()` (`R/penalty.R:54-86`) still computes `rate = -log(sd_alpha) / sd_u`
(line 83) exactly as the help page describes for an exponential prior. The penalty is actually
*applied* in `src/drmTMB.cpp:93-121` (`drm_phylo_penalty_value`), called at `src/drmTMB.cpp:1124` and
`:5155`. Its per-component term is `pen += lam * sd_k - log_sd_phylo(k) - log(lam)` (line 102), where
`sd_k = exp(log_sd_phylo(k))`. This is the negative log-density of `log(sd)` induced by an
Exponential(`lam`) prior on `sd` *with the change-of-variables Jacobian* (`d(sd)/d(log sd) = sd`)
included — i.e. `-log(lam) - log(sd) + lam*sd`. As a function of `sd`, `lam*exp(-lam*sd)*sd` is exactly
proportional to a `Gamma(shape = 2, rate = lam)` density (`lam^2 * sd * exp(-lam*sd)`, since
`Gamma(2) = 1`), which has its mode at `sd = 1/lam`, not at `sd = 0` — matching Russell's measured
"direction reversed" and "implied prior mode `1/rate`" exactly. Whether the code should drop the
Jacobian term (so the penalised optimum tracks a true Exponential-on-`sd` mode at 0, the standard
penalised-ML convention) or the help page should describe the Gamma(2) object it currently fits is an
open call. `git log --oneline 945da24f..HEAD` touches neither `R/penalty.R` nor the `drm_phylo_penalty_value`
lines of `src/drmTMB.cpp`. No existing-issue match found (checked "phylo_penalty", "PC prior",
"Gamma(2" in open-issues.json).

## Proposed fix (Russell's, if stated)
Not stated which side to fix — "the two do not currently describe the same object." Code fix: drop the
`- log_sd_phylo(k)` Jacobian term so the penalty is a plain Exponential(`lam`) shrinkage toward zero on
`sd` reparametrised for `log_sd` optimization. Documentation fix: describe the fitted object as
`Gamma(2, rate)` and its consequences (mode at `1/rate`, not shrinkage-to-zero).

## Status note at posting (2026-09-13)
A first attempt on branch `claude/audit-dinnage-wave1-20260913` (wave 2a) corrected the documentation to
describe a Gamma(2, rate) penalty; the independent Fisher review REJECTED that commit and it was reverted
(`9ed334009`): `src/drmTMB.cpp:86-90` and `docs/design/172-phylo-penalized-map.md:44-53` both state the
`-log(sd)` term is the log-Jacobian of the documented exponential PC prior, so the documented calibration
`P(sd > sd_u) = sd_alpha` is true of the prior. The defect Russell measured (mode at `1/rate`, pull away
from zero) is the maximum-a-posteriori estimate in `log(sd)` not being parameterisation-invariant. That is
a design decision for Shinichi (penalise on the sd scale, or document the log-scale MAP), tracked here.

TITLE: [Dinnage audit Mi-15] `confint.drmTMB()` returns a 13-column data frame where `stats::confint()` promises a 2-column matrix
LABELS: audit-dinnage, enhancement, minor
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row Mi-15; severity minor).

## What Russell found
`confint()` returns a 13-column data frame where `stats::confint` promises a 2-column matrix, breaking the
generic's documented contract for code that expects the base return shape (e.g. `insight`/`broom`-style
tooling).

## Where (at 945da24f)
`R/profile.R` (`confint.drmTMB`).

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `confint.drmTMB` is defined at `R/profile.R:404`; its documented Value (`man/confint.drmTMB.Rd:167`)
is "A data frame with columns `parm`, `level`, `lower`, `upper`, ..." -- still a multi-column data frame,
not the 2-column matrix `stats::confint()`'s generic contract documents (`matrix` with columns named by
the quantiles, one row per parameter). No `simplify` argument or `tidy()`/`as.matrix()` companion exists in
`R/profile.R` for callers that want the base shape. `git log --oneline 945da24f..HEAD -- R/profile.R
man/confint.drmTMB.Rd` shows no commit adding a simplified return path. No existing-issue match: `gh issue
list --search "confint"` returns performance/parallelization issues (#1247, #1236, etc.), none about the
return shape.

## Proposed fix (Russell's, if stated)
"`simplify = TRUE` + `tidy()`" -- add an argument or companion method that returns the base 2-column
matrix shape for callers that want it, while keeping the richer data frame as the default/alternative.

## Acceptance
- [ ] `confint.drmTMB()` gains a documented path (argument or method) to obtain a 2-column
      `lower`/`upper` matrix matching `stats::confint()`'s generic contract

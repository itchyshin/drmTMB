TITLE: [Dinnage audit S8] REML = TRUE returns NA Wald confint() on mean coefficients with no explanation
LABELS: audit-dinnage, documentation, moderate
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row S8; severity moderate).
Supporting working: a plain Gaussian location-scale fit with and without a random effect, `REML = TRUE`.

## What Russell found
`confint()` on a mean coefficient of a `REML = TRUE` fit gives `lower = upper = NA` with `conf.status =
"wald_unavailable"`, and profiling errors with `"missing_tmb_parameter"`. This is not meta-specific — it
reproduces on a plain Gaussian fit. `summary()` and `vcov()` *do* return finite SEs for those same
coefficients, so the refusal is deliberate rather than a missing quantity, and `method = "bootstrap"`
works and lands where the ML Wald interval does. The gap is that nothing tells the user this in advance.

## Where (at 945da24f)
`man/drmTMB.Rd` (`REML` entry).

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. The mechanism is in code: `confint.drmTMB`'s Wald branch (`R/profile.R:2182-2228`) reads
covariance from `drm_sdreport_cov_fixed(object)` (`object$sdr$cov.fixed`, `R/methods.R:2394-2401`) —
under REML, mean coefficients (`beta_mu`) are integrated into TMB's `random =` block and are absent
from `cov.fixed`, so `positions` resolve outside it, `interval_ready` is `FALSE`
(`R/profile.R:2194-2196`), and `conf.status` is set to `"wald_unavailable"` (`R/profile.R:2228`). By
contrast, `vcov.drmTMB` and `summary()`'s SEs read from `drm_sdreport_cov_coefficients(object)`
(`R/methods.R:2404-2419`), which under REML returns `object$sdr$cov` — the FULL sdreport covariance,
including the REML-integrated `beta_mu` block — so they report finite SEs for the same coefficients
`confint()` refuses. `man/drmTMB.Rd`'s `REML` entry (lines 118-158) documents which families/routes
accept `REML = TRUE` at length but says nothing about this `confint()`/`vcov()` split. `git log
--oneline 945da24f..HEAD -- R/profile.R R/methods.R man/drmTMB.Rd` was inspected for anything mentioning
this split; none found. Not independently verified here: Russell's specific claim that `method =
"bootstrap"` lands where the ML Wald interval does — that requires a live R fit, which this review was
told not to run. No existing-issue match found (checked "wald_unavailable", "missing_tmb_parameter",
"REML.*confint" in open-issues.json; #1201 is about a different question — Wald SE *construction*
differing between the TMB and Julia engines for REML mean coefficients, not `confint()` refusing an
interval — so not a match).

## Proposed fix (Russell's, if stated)
"One sentence in `?drmTMB`'s `REML` entry", which currently states the marginalisation mechanism but
not the consequence for `confint()`.

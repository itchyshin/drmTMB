TITLE: [Dinnage audit Mi-10] `simulate.drm_pair_association()` leaks the RNG seed with a bare `set.seed()` and no `on.exit` restore
LABELS: audit-dinnage, bug, minor
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row Mi-10; severity minor).
Supporting working: read against the package's own documented idiom.

## What Russell found
`simulate.drm_pair_association()` leaks the RNG seed -- a bare `set.seed()` with no `on.exit` restore --
while the package writes the correct idiom (save `.Random.seed`, restore via `on.exit`) twice elsewhere
and documents it as a contract in a 20-line comment.

## Where (at 945da24f)
`R/associate-pairs.R`.

## Since-audit status on main (4bfb9d721, 2026-09-13)
PRESENT. `simulate.drm_pair_association()` (`R/associate-pairs.R:683-`) contains `if (!is.null(seed)) {
set.seed(seed) }` with no accompanying `on.exit()` to restore the caller's prior `.Random.seed` -- calling
this function with a `seed` argument permanently advances/resets the caller's global RNG stream, unlike
`simulate.drmTMB()` and other simulate methods in the package (confirmed the correct save/restore idiom
exists at least once elsewhere via `grep -n "on.exit" R/associate-pairs.R`, which finds only an unrelated
`unlink()` cleanup at line 1282, not an RNG restore). `git log --oneline 945da24f..HEAD --
R/associate-pairs.R` shows no commit adding an `on.exit` RNG restore. No existing-issue match: `gh issue
list --search "RNG seed"` and `--search "simulate.drm_pair_association"` return nothing.

## Proposed fix (Russell's, if stated)
"1 `on.exit`" -- save the caller's `.Random.seed` before calling `set.seed()` and restore it via
`on.exit()`, matching the package's own documented idiom used elsewhere.

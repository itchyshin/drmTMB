TITLE: [Dinnage audit M1] weights() sit inside the mi() mixture, moving the MLE at constant weight
LABELS: audit-dinnage, bug, major
---
Reported by Russell Dinnage, independent evaluation of drmTMB 0.7.0 at 945da24f
(https://github.com/rdinnager/drmTMB_eval/blob/main/REPORT.md §4, Appendix A row M1; severity major).
Supporting working: none cited beyond the reproduction in §4

## What Russell found
Multiplying every case weight by a constant must not move the MLE (equivalently, `weights = 2` must
match literal row duplication), and this holds exactly for drmTMB's plain weighting. It breaks the
moment `mi()` (missing-predictor imputation) is used in the same formula: the coefficient on the
imputed predictor moved monotonically by 0.065 across a 4x weight range (`w = 0.5, 1, 2`), while the
no-`mi()` control matched row duplication exactly. The mechanism is that `weights(i) *` multiplies
each mixture **leaf** density before `logspace_add()` combines them, i.e. the code computes
`log(p1*f1^w + p0*f0^w)` instead of the correct `w*log(p1*f1 + p0*f0)` — the weight is on the wrong
side of the mixture. `check_drm()` returns identical warnings on the correct and incorrect fits. This
is the only finding in the report that biases a point estimate through the likelihood itself; it is
held at Major (not Critical) only because the measured bias was sub-SE at the weights tested — Russell
says to promote it to Critical if realistic inverse-probability weight dispersion exceeds ~1 SE.

(`gh issue list --search "mi() mixture"` / "weights" returns nothing on point).

## Proposed fix (Russell's, if stated)
Move `weights(i) *` outside the mixture: `nll -= weights(i) * log_denom;` (weighting the combined
mixture log-density rather than each leaf), weight the imputation-prior term the same way, and add a
test asserting `weights = c` and `weights = 1` give identical coefficients under `mi()`. Estimated
3 lines plus 1 test.

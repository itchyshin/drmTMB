**Reconciled with D-252 first, then fixed.** `docs/design/275-repeatability-scale-and-residual-variance.md` (`37b5d7ce6`, independently reviewed) answers the four checks above for drmTMB:

1. *Which scale, and is it documented?* Both loci — `summary()$derived`'s variance-share row and the `heritability()`/`icc()`/`repeatability()` accessors — are **Gaussian-only**, so for the response the latent, expected-data and observed-data scales coincide; the delta-method runs on the working log-SD scale. The help pages now say what the residual variance is.
2. *Is a link or distribution variance added?* No, on either path (verified by reading both computations in full).
3. *Is a latent value refused where Eq 4 is defined?* Non-Gaussian fits are refused by an explicit error, not by `NaN`, so drmTMB neither computes nor mislabels a latent quantity. Adding Eq 4 latent-scale support for non-Gaussian families (and Eq 24 liability / Eq 26–28 observed) is a feature decision; the note gives the formulas it would need.
4. *Phylogenetic signal?* The accessors share one residual helper; the fix below applies to a phylogenetic random intercept on `sigma` as well (unit-diagonal correlation, the default path).

**Russell's S2 measurement is a different, scale-independent defect, now fixed** (`3192db3f6`): `drm_constant_residual_sigma()` returned `exp(b0)`, the median scale, so with a random intercept on `log(sigma)` of SD `omega` the denominator was too small by `exp(2 omega^2)`. It now returns `exp(b0 + sum omega_k^2) = sqrt(E[sigma^2])`; the accessors, which rebuilt the residual from `beta_sigma` themselves, now use the marginal form in both the estimate and the delta-method SE. Random slopes on `sigma`, or a structured effect whose correlation diagonal is not one, give `NA` with a message naming why. Red-first test with four fixtures (ordinary random intercept, `sigma ~ 1` control, random slope, phylo-on-sigma); 467 existing heritability/summary assertions still pass.

Twins: DRM.jl requires `sigma ~ 1` with exactly one coefficient and cannot reach this case; gllvmTMB #1276 carries the D-252 rename. The vocabulary question for non-Gaussian families stays open here, as a feature decision rather than a bug.

Decision (2026-09-14, recorded as D-266): **keep the code, document the estimator** — Fisher's option A.

`d44a495be` rewrites the Details of `?drm_phylo_penalty`: the prior on each phylogenetic SD is the documented exponential (PC) prior with rate `-log(sd_alpha)/sd_u`, so `P(sd > sd_u) = sd_alpha` holds exactly; the penalty is evaluated on `log(sd)` with the change-of-variables Jacobian, so the reported penalised `sd_phylo` is the mode in `log(sd)`, is never zero, and sits at `1/rate` (0.334 at the defaults) under a flat likelihood; a penalised fit must not be used to test a null of no phylogenetic signal. The page no longer advertises shrinkage toward "no phylogenetic variance" as a property of the point estimate.

Option B (drop the Jacobian so the mode shrinks to zero) is parked, not rejected: it is a likelihood change, makes the estimator boundary-capable at `sd = 0`, changes every existing penalised fit, and needs bias and coverage evidence at a true null and a true nonzero SD before it could ship. It reopens only if the package's contract is decided to be "this penalty shrinks toward zero".

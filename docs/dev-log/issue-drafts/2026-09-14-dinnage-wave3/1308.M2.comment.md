Status (2026-09-14, second audit arc, branch `claude/audit-dinnage-wave1-20260913`, draft PR #1361).

Fixed in `0526baa2f`. One internal helper applies the existing R-side soft clamp to the sigma-type linear predictor of every family in `drm_clamped_scale_families()` at the two live prediction paths — `predict.drmTMB()` (through which `sigma()`, `residuals()`, `observation_sigma()`, the lognormal `fitted()` path and `predict(newdata)` all pass) and the marginal predictor `simulate()` uses by default. The third candidate path only ever sees `sd(...)` dpars and cannot fire.

Red on the previous code with the clamp forced to bind (`tests/testthat/test-dinnage-audit-m2.R`): a hand-recomputed Gaussian log-likelihood under `sigma(fit)` missed `logLik(fit)` by 297 nats, `sigma()` reported a maximum of 98.2 against a clamped 3.7, the Pearson-residual SD was 2.02, and `simulate()` draws at clamped rows were off by up to 25×. Green after; an inactive-clamp control is bit-identical before and after.

Two follow-up commits, each after a fresh independent review: `predict_parameters()` had kept a raw-predictor Wald interval around the clamped estimate (60/200 rows with the estimate outside its own interval on a clamp-active fit); clamping the endpoints turned out worse (zero-width intervals at saturated rows, measured coverage 0), so clamp-bent rows now return `NA` endpoints flagged `conf.status = "clamp_limited"` and in-band rows keep the ordinary Wald interval. `predict(dpar = "sd(group)")` for a modelled random-effect scale now reports the clamped value the kernel and the fit's own `sdpars` use (before: up to 8× off). Still on the raw predictor, recorded as follow-ups rather than fixed here: the response-scale `profile()` output for `sigma` (no `clamp_limited` refusal for residual `log_sigma`), the Julia-bridge scale target, `summary_parameter_delta_derivative()`, and `check_drm()`'s clamp detector, which never reads a modelled `sd(group)` scale.

The help pages now say what the value is: the scale the likelihood evaluated. When `check_drm()` reports the clamp active, the estimate itself is still not trustworthy — reporting the clamped value makes the fit honest, not correct; the rescale advice from C1 is what makes it safe.

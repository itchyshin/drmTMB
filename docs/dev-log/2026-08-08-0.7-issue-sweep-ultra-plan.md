## Classification and action schema

Every ledger row must carry all of these fields: issue number/title; thread URL
and latest relevant comment permalink; current claim; current-main evidence
with commit and file:line/test/CI receipt; release disposition; issue action;
owner; next action; confidence; and a one-sentence non-coverage statement.

**Release disposition** is exactly one of:

1. `blocker_candidate` — unresolved defect in the intended current 0.7 surface,
   or a mandatory pre-freeze release-gate action.
2. `not_blocker` — completed/superseded work, clearly bounded future work, or a
   safely rejected/documented unsupported surface.
3. `owner_decision` — evidence cannot decide whether the issue belongs before
   the candidate freeze.
4. `protected_deferred` — outside this arc or owned by a protected foreign lane.

**Issue action** is separate from release disposition: `retain_blocker`,
`retain_post_0.7`, `retain_nonblocking_backlog`, `retain_owner_decision`,
`close_done`, `close_superseded`, or `no_touch_protected`. Thus a completed
issue can be `not_blocker + close_done`, while a future enhancement can be
`not_blocker + retain_post_0.7`.

No row may be classified from its title, and no row may end as `unknown` or
blank. Low-confidence rows become `owner_decision`; they are not closed.

## The one user-surface item

**#983 — the estimator round-trip errors.** A fit reports `f$estimator == "ML"`
(`R/drmTMB.R:1036`, asserted in `test-mspl-estimator.R:68`), but `drmTMB()` validates with
`match.arg(x, c("ml", "mspl"))` (`R/mspl-estimator.R:162`), which is case-sensitive. Reading the
setting off a fit and passing it back errors. Effort trivial-to-small.

**Fix it on the input side, not the output side.** Accept the reported spelling case-insensitively;
do **not** change what `$estimator` reports. The AGHQ arc deliberately kept the token `"ML"` because
a new token flips a family-map slope to "absent" in the capability ledger. Changing the reported
value would ripple into the ledger; accepting `"ML"` on input would not.

Touches shipped files (`R/drmTMB.R`, `R/mspl-estimator.R`) — see the re-freeze note below.

## Items needing a documented limitation, not a fix

  Document the substitution where the estimator is described.
- **#967** — `confint()` profile intervals are unimplemented for ordinal cutpoints. Document as a

- **#870** — `offset()` is gated on `dpar == "mu"` with no family conditional
  (`R/drmTMB.R:6881`), but the error message at `R/drmTMB.R:14976` frames offsets as
  count-exposure-only. The code is not broken; the message undersells the scope. Fix the message.
- **#802** — no coverage evidence for row-specific regression-`rho12` intervals. The intervals exist
  via `newdata`; the gap is evidence. Confirm the existing limitation statement carries into the
  0.7.0 scope docs.

## A correction to a premise this triage started from

The 2026-08-10 handover describes the MSPL work as "internals which export **no** symbols — internal
only", and that framing was passed to all three reviewers. **It is misleading.** MSPL is reachable
from the exported API through a documented argument: `estimator = c("ml", "mspl")` appears in
`man/drmTMB.Rd:18`. No *new* symbol is exported, but MSPL behaviour is user-facing, so MSPL issues
(#983, #984, #977) are triaged as user-facing rather than internal.

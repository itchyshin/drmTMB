## 3a. Decisions and Rejected Alternatives

- Kept the previous attempt's two scripts unchanged (md5 identical local vs Totoro:
  `f280cbd3…` / `2e621612…`) because the R call is byte-for-byte the fixture's own
  `r_call` and the Julia call is the fixture test's line 86; rewriting them would have
  broken the "same model on both engines" argument.
- Discarded the previous attempt's rep JSONs and logs (moved to scratch, not committed)
  and replaced them with this run's; kept its `install-R.filtered.log` and
  `instantiate.log` because they document the setup step, which this run re-verified by
  `packageDescription()` (RemoteSha = the `v0.7.0` tag) and a clean `git status` at the pin.
- `q4_vcov = false` on the Julia side (the fixture test's call) rather than `true`: it is
  the bridge's default for this route and its vcov is fenced (#495); recorded as a caveat
  instead of changing the call shape.
- Did not use `taskset`: the environment pins gave 99–100 % CPU on one core; affinity
  pinning would have been a different knob from the design.
- Did not `rm -rf` on Totoro (guard); the previous attempt's `out/`, `logs/` stay beside
  `run2/` under `~/parity_joint/`.

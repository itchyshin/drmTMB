# After-task: batch 25, Julia Gamma/NB2 structured slope-only SD and R bridge admission

Date: 2026-11-02. Lane: codex/general-sd-regression (R bridge); DRModels.jl worktree `general-sd-julia`, same branch name.

## What was asked

Julia counterparts of native drmTMB structured slope-only SD regression for (1) Gamma `phylo(0 + x | sp)`, `relmat(0 + x | id, K)`, `spatial(0 + x | site)` and (2) NB2 `relmat(0 + x | id, K)`, each with `sd(id, level = ...) ~ z`; then R-bridge admission with one live native-vs-Julia check per route.

## Julia (DRModels.jl commits 53b992349 and 2ffbbcb5a on codex/general-sd-regression)

- Gamma: `_drm_gamma_structured_sd_regression` now accepts the slope-only marker for phylo, relmat and spatial. The loading is the slope column times `exp(Z alpha)`; the existing sparse-Laplace spine is reused.
- NB2: `_drm_negbin2_sd_regression` accepts relmat slope-only and reuses the NB2 structured Laplace route.
- Kernel scale, recorded because it decides parity: relmat K enters RAW (the slope-only branch passes `normalize = false`; the relmat intercept routes keep their correlation-rescaled K, unchanged). Spatial slope-only uses the native fixed kernel `exp(-d / median positive distance) + 1e-6 I`, also raw, from `coords` only (a precomputed `K` is refused). Phylo uses the raw tree covariance.
- `predict`, `predict_parameters` and the bridge label renderer admit the slope-only markers for these families.
- Tests: `test/test_gamma_structured_slope_sd_regression.jl` (three providers) and `test/test_nb2_relmat_slope_sd_regression.jl`. Each compares `fit.nll(theta)` with an independently coded dense Laplace objective (tolerance 4e-3 Gamma, 2e-3 NB2), and checks that a correlation-rescaled K would give a different objective (raw K is really used), plus refusals.

## R bridge (this patch)

- `R/julia-bridge.R`: new shape gates `drm_julia_gamma_relmat_sd_slope_route_admitted`, `drm_julia_gamma_spatial_sd_slope_route_admitted`, `drm_julia_gamma_structured_sd_slope_route_admitted`, `drm_julia_nbinom2_relmat_sd_slope_route_admitted`; wired into the typed-label key, the `resd` label exemption, the marker-slope refusal, the structured payload (coefficient, term-type and family checks) and the coordinate-spatial to relmat-K conversion. Gamma spatial is admitted only for a slope term; the Gamma spatial intercept is still refused.
- No unit-diagonal refusal for these routes: Julia uses raw K, as native does (unlike the Poisson relmat slope route, which still rescales).
- `tests/testthat/test-julia-b18-relmat-nb2-slope-sd-bridge.R`: the family-guard probe used `"gamma"`, which is now admitted; it uses `"student"` instead.
- New `tests/testthat/test-julia-b25-gamma-nb2-slope-bridge.R`: gate/payload tests plus three live checks.

## Not admitted, and why

- Gamma phylogenetic slope-only SD: the Julia route is correct against its dense oracle, but on the raw tree covariance (Julia warns when tree height is not 1), whereas native uses the correlation matrix, so scaling differs unless the tree is ultrametric with height 1. The bridge does not marshal Gamma phylogenetic SD at all. Refused with the existing marker-slope error.
- NB2 spatial and phylogenetic slope-only SD: no Julia route.
- Julia marginal simulation and bootstrap for the new Gamma/NB2 structured slope fits: not added; the simulators refuse these markers (they do not fall back to a mismatched kernel). Not tested beyond that.

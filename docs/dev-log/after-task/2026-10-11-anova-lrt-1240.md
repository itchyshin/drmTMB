# Wire `anova.drmTMB()` to the likelihood-ratio test (#1240)

## Goal

Replace the always-abort `anova.drmTMB()` with a likelihood-ratio table, as the
owner decided on #1240 (option (a), 2026-10-11). The reader is a user coming
from `lme4` or `glmmTMB` who expects `anova(m0, m1)` to test nested ML fits.
This PR is stacked on #1507 and should merge after it.

## Implemented

`anova(m0, m1, ...)` now orders the fits by number of parameters and tests each
against the one before it with `drm_lrtest()`, so that helper's guards apply
(same observations, REML mean structure, MAP, MSPL). The table has `npar`,
`logLik`, `deviance`, `Chisq`, `Df` and `Pr(>Chisq)`, with the per-row p-value
method in `attr(, "p.method")`. Two additions beyond `drm_lrtest()`:

- ML and REML fits are never mixed (`drmTMB_anova_estimator_error`), as in
  `lrt_boundary()`.
- When the larger model adds random-effect standard deviations, a
  `drmTMB_anova_boundary_warning` is signalled. If exactly one or two SDs are
  added, no correlation changes, and the extra-parameter count equals the
  number of SDs, `Pr(>Chisq)` is the chi-bar-square mixture from
  `lrt_boundary()` (`"chibar"`). Otherwise the naive chi-square p-value is kept
  and the warning says it is conservative (`"chisq"`).

Refusals: a single fit, fits with equal parameter counts, `test` other than
`NULL`, `"Chisq"` or `"LRT"`, and `engine = "julia"` fits. `anova()` on a Julia
fit still refuses with its own message.

## Checks Run

`test-anova-lrt.R` fails on the previous build (every test errors with the old
"not implemented" abort) and passes here. It checks the table against
`drm_lrtest()` and `pchisq()`, argument-order independence, three-model
sequences, the chi-bar p-value equalling `lrt_boundary()` (and half the naive p
for one added SD), the "mixture does not apply" branch, and every refusal.
`test-model-comparison.R`, `test-lrt-boundary.R`, `test-parity-matrix.R` (its
byte-identical regeneration test runs against the pin) and the skip-census
test pass.

## What Did Not Go Smoothly

The generic is `anova(object, ...)`, so only the first argument has to be
called `object`; the test for named fits uses `anova(m0, full = m1)`.

## Remaining

Extending `anova()` to `engine = "julia"` fits is an owner decision (listed in
the julia capability row). A parametric-bootstrap p-value for boundary pairs the
mixture does not cover is future work.

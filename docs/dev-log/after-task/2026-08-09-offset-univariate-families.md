# After-task — `offset()` for all univariate families (Tiers A+B)

Meta: 2026-08-09 · Claude · branch `claude/offset-univariate-families` from `origin/main@ac363cadb`

## 1. Goal

Accept a standard R `offset()` term in the `mu` formula of every univariate family, with
per-link documentation that is honest about what an offset *means* for each link, landing as
0.7.0 release bytes. Truncated/hurdle NB2 and all bivariate families stay deferred.

## 2. Implemented

**Foundation.** `make_tmb_data_core()` fell back to `numeric(1)` when a spec carried no
offset. That was safe only while 13 of 18 families never read `offset_mu` in the template;
the first branch to add it would have size-mismatched inside Eigen at run time. The fallback
is now `rep(0, length(spec$y))` (`R/drmTMB.R`). A guard was also added rejecting `offset()`
combined with Gaussian sufficient-statistic aggregation, which already consumes a separate
`offset_mu_agg` slot on that path.

**Ten families, one repeatable three-step pattern**, copied from the poisson reference:
pass `allow_offset` at the builder's `drm_reject_phase1_terms()` call, populate
`spec$offset$mu` via the existing `drm_model_offset()`, and prepend `offset_mu +` to that
`model_type`'s linear-predictor initialiser in `src/drmTMB.cpp`.

- **Identity/log links:** gaussian (`model_type` 1), student (3), skew_normal (17),
  lognormal (4), gamma (5), tweedie (16).
- **Logit links:** beta (10), zero_one_beta (15), beta_binomial (14), cumulative_logit (13).

Gaussian was the only non-uniform C++ edit — it assigns through a `fixed_mu` intermediate
with a sparse-X branch, so the change is `mu = offset_mu + fixed_mu`. `cumulative_logit` was
the only builder with two `mu` gates (one inside a structured-marker branch); both were
opened.

**No prediction-side work was needed.** `drm_prediction_offset()` and the `emmeans`/profile
paths were already family-agnostic and start working the moment `spec$offset$mu` is
populated.

## 6. Tests of the Tests

The load-bearing assertion is an exact identity, not a tolerance-fitted number. For any link
`g` and constant offset `c`, `g(mu) = c + b0 + b1 x` is the same model as
`g(mu) = b0' + b1 x` with `b0' = b0 + c`. So fitting with `offset(c)` must lower the
intercept by **exactly** `c` and leave every slope untouched.

That makes the test self-red-teaming in a useful way: a mis-plumbed offset (dropped,
double-counted, or applied after the inverse link) misses by an amount of order `c` itself —
0.35 here — against a tolerance of 1e-3. The failure signal is ~350x the noise floor.

**Red test performed and passed.** The gamma builder's `offset = list(mu = offset_mu),`
hand-off was deleted — reproducing the exact "offset parsed but never reaches TMB" failure
mode, which is the most plausible way this could break silently, because the formula still
parses and the fit still converges. The suite returned **2 failures, 0 errors**: precisely
gamma's intercept and slope assertions, with every other family still green. `R/drmTMB.R`
was then restored and verified byte-identical to its backup.

This is the check that matters. A dropped offset does not error, warn, or fail to converge;
it just silently answers a different question. The oracle is what makes it visible.

Two negative controls also ship, neither of which existed before this arc: the deferred
families must still **error**, and Gaussian aggregation + offset must **error**. Before this
arc, zero tests covered offset rejection for `truncated_nbinom2` or `beta_binomial` — the
rejection was enforced only by an untested default argument.

## 8. Consistency Audit

Applying the Rose principle to "one family's offset gate is wrong, assume ten more are":

- **All 18 family return-lists** in `make_tmb_data_core()` were checked for the `offset_mu`
  hand-off — all 18 already receive it; the data reached every family and was simply unused.
- **All ~23 `drm_reject_phase1_terms()` call sites** were enumerated to find which opted in.
- **Every `model_type` branch** in the template was tabulated for whether it adds
  `offset_mu`, which is what established that 13 did not.
- **Every builder** was checked for `y`-subsetting that would misalign the offset against
  `spec$y`. Four create a `y_obs` subset, but it is validation-only in all four; `spec$y`
  stays at full model-frame length, matching the poisson pattern. Had any assigned the
  subset to `spec$y`, the offset would have silently misaligned.
- **All offset-mentioning surfaces** were swept for the same overclaim class: `README.md`
  (no mention), `NEWS.md` (count-only, correct), `vignettes/formula-grammar.Rmd`
  (count-only, correct), four design docs (count-only, now generalised). Only the roxygen
  and its generated `.Rd` carried the false claim.

## 9. What Did Not Go Smoothly

- **My first `beta_binomial` fixture drew plain binomial counts**, leaving the
  overdispersion `sigma` at its boundary and producing false-convergence warnings. The
  coefficients were exactly right throughout — the DGP was wrong for the family, not the
  code. Fixed by drawing from a beta-binomial.
- **Sharing one RNG stream across the fixture list** made a given family's convergence
  depend on which families were generated before it. Isolating a family reproduced nothing;
  the warnings moved when the list changed. Each family now seeds its own draw.
- `bf()` captures its arguments, so `as.formula()`-built formulas are rejected. Fixtures
  build the whole call textually instead.
- A first pass at the aggregation-guard probe used `aggregate_gaussian = TRUE` as a
  top-level `drmTMB()` argument; it is a `drm_control()` field, so the probe silently tested
  nothing until corrected. The guard itself was fine.

## 10. Known Residuals

- **Tier C (truncated/hurdle NB2) and Tier D (bivariate) remain unimplemented**, by design,
  with the blocking question recorded rather than resolved.
- **The oracle proves the offset enters the linear predictor correctly; it does not prove
  the *interpretation* is useful for logit-link families.** A logit-scale offset is a
  calibration term, and whether users want one on `beta()` or `cumulative_logit()` is a
  judgement the docs now state but no evidence supports either way.
- **No coverage or interval evidence was gathered, and none is claimed.** An offset adds no
  parameters, so no ledger cell moved — verified, not assumed.
- `inst/CITATION` still falls back to a stale `"0.1.4"` version string; noticed in passing,
  not in scope, recorded next door in the 0.7 candidate lane.

## 11. Team Learning

- **A "flip the gate" task is rarely only an R change.** The R data plumbing already reached
  all 18 families, which made the change *look* like a one-line gate flip. The real work was
  10 template edits plus a latent length trap. Trace the value to its consumer before sizing.
- **A length-1 dummy is a loaded gun in a template with per-branch consumers.** It is safe
  exactly while nobody reads it, and the failure mode when someone does is a runtime Eigen
  mismatch, not a compile error.
- **Check the original commit's after-task log before calling an exclusion an oversight.**
  The truncated/hurdle gap was documented deliberate work with a stated reason and a "later"
  note. Ten minutes of `git log --grep` reframed the whole arc from "fix a bug" to "resume a
  scheduled slice".
- **Prefer an exact identity to a fitted tolerance when one exists.** The constant-offset
  identity is link-agnostic, so one oracle covers ten families and its failure signal is two
  orders of magnitude above the noise.

## 12. Cross-Product Coverage

`offset()` is cross-cutting: it is a transformation of the location linear predictor, so it
touches every downstream surface of every family it is enabled for.

**Covers ✓**

- Fitting and coefficient recovery for all 10 newly enabled univariate families, both links
  represented, verified by the constant-offset identity.
- `spec$offset$mu` storage at full model-frame length for all 10.
- **Composition with an ordinary random intercept**, on one identity-link and one log-link
  family (gaussian, gamma; 40 groups × 8). The offset is added to eta before random-effect
  contributions are folded in, and the constant-offset identity survives at machine
  precision, so the two do not interfere.
- `predict()`/`fitted()` with and without `newdata`, verified on gamma (log link) by the
  exp-scaling identity; the prediction path is family-agnostic and shared.
- Non-finite offset rejection (shared `drm_model_offset()` guard).
- Rejection for truncated/hurdle NB2, bivariate families, Gaussian aggregation, and every
  dpar other than `mu`.
- Ledger census invariance.

**Does NOT cover ✗**

- **Structured effects** (`phylo()`, `spatial()`, `animal()`, `relmat()`) combined with an
  offset, for any family. Ordinary random intercepts are now covered (below); structured
  providers are not exercised.
- **`emmeans` grids** for the newly enabled families. Existing emmeans offset tests cover
  only poisson/nbinom2/binomial; the code path is shared and family-agnostic, so this is
  untested-but-expected-to-work, not verified.
- **Profile and bootstrap intervals** on offset models for the new families.
- **`mi()` missing-predictor and missing-response routes** combined with an offset, for the
  new families. Existing coverage is poisson/binomial/nbinom2 only.
- **`weights` × `offset` interaction** for the new families.
- **Any coverage, calibration, or interval claim.** None gathered, none made.
- **Julia bridge parity** for offsets on any family.

## The one intended breakage

`test-julia-slope-nongaussian.R`. DRM.jl #621 added `_check_phylo_re_lhs`
(`src/gaussian_ranef.jl`), which refuses `phylo(<not 1> | g)` on univariate routes.
Verified read-only that this function **exists at the new pin and does not exist at
`77513aa0`** — which is precisely why the old pin fitted the construct silently, as an
intercept-only model with `x` discarded.

The test now asserts DRM.jl's specific wording rather than a finite fit. It keeps the
#1127 principle intact — engine availability is still decided by
`drm_skip_live_julia()`, and an engine error is still a test error, not a skip. It
does not catch-and-ignore: because it matches the refusal text, any *other* engine
failure still fails the test. Negative controls reject `coef_labels` (the previous
live breakage on this exact cell), `Failed to precompile`, and `Package DRM not found`
so none of them can masquerade as the refusal.

## A finding this surfaced, deliberately not acted on

DRM.jl #624 rewrote the univariate-Gaussian REML refusal so that it **enumerates**
what REML is available for. That list is **wider than `drm_julia_reml_supported()`**
in three cells: bivariate structured q=2, Poisson `(1 | g)`, Poisson
`phylo(1 | species)`. Before #1149 those silently downgraded to ML; after it they
raise. That is the intended direction of the trade, but the error is avoidable.

Filed as **#1152** rather than fixed here, for a reason: DRM.jl's message is its own
claim about itself, not a measurement. Widening a gate on an unverified docstring
risks the *opposite* and more dangerous fault — forwarding REML to a cell that quietly
downgrades. #625 now makes verification direct (request REML, read back
`estim_method`), so that follow-up can carry real evidence.

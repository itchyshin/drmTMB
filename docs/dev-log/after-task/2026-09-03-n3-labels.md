# After-task: N3 -- `objective_at()`/`start=` reach `rho12` and the q4 phylo covariance block

## What was built

The A5 cross-engine receipt
(`docs/dev-log/evidence/julia-r-parity/ayumi-target/2026-09-02-a5-cross-engine-receipt.R`)
found that `objective_at()` (`R/objective-at.R`) and `drm_control(start = ...)`
(`R/control.R`, applied via `drm_translate_public_start_override()`, R/drmTMB.R)
could not name two things a bivariate q4 phylogenetic REML fit has: `biv_gaussian`'s
`rho12` fixed effect (`beta_rho12` carried no model-matrix column names) and the q4
phylogenetic covariance block (`log_sd_phylo`/`theta_phylo`, which live in
`spec$structured$phylo_mu`, outside `spec$random` entirely). Both aborted with
"Unknown public start label". The receipt worked around this by addressing
`beta_rho12`/`log_sd_phylo`/`theta_phylo` directly by internal TMB parameter name.
This closes both gaps in the public label vocabulary itself.

1. **`rho12` reaches the existing `fixef:` family.** `beta_rho12` is now named
   with `colnames(X_rho12)` at start-build time (`biv_gaussian_start()`,
   R/drmTMB.R) -- exactly the way `beta_mu1`/`beta_mu2`/`beta_sigma1`/
   `beta_sigma2` already are (from `lm.fit()`/`gaussian_sigma_fixed_start()`
   instead). No new label family was needed: `drm_resolve_public_start_target()`'s
   existing `fixef:<dpar>:<column>` branch is already generic over `dpar`, so
   `fixef:rho12:(Intercept)` works the moment the component is named. `rho12` is
   never folded into the REML Laplace random block (only `beta_mu1`, `beta_mu2`,
   `beta_sigma1`, `beta_sigma2` are -- see `drm_fit_df()`), so it is honored under
   `REML = TRUE` too, unlike `fixef:mu:`.

2. **Two new label families for the phylo covariance block**:
   `phylo_sd:<axis>` and `phylo_cor:<axis1>:<axis2>`, parsed by
   `drm_parse_public_start_label()` (their own arity -- 2 and 3 segments -- ahead
   of the generic `family:dpar:target` pattern) and resolved by new branches in
   `drm_resolve_public_start_target()` (R/drmTMB.R). Full mapping, transform
   rules, and worked examples are in design 35's new "Phylo Covariance Block"
   section. Summary:
   - `phylo_sd:<axis>` maps to `log_sd_phylo[index]`, natural (positive) scale,
     `log()`-transformed -- same convention as `sd:`.
   - `phylo_cor:<axis1>:<axis2>` maps to `eta_cor_phylo` (q = 2) or a
     `theta_phylo` entry (q > 2). For q = 2 and for q > 2 block-diagonal layouts
     (each labelled 2-endpoint block), the mapped entry IS a bounded correlation
     directly, so the transform is the same `atanh(value / 0.999999)` as `cor:`.
     For q > 2 **dense** (a single shared-label block spanning all q axes -- the
     A5 fixture's shape), `theta_phylo` is TMB's `UNSTRUCTURED_CORR_t`
     Cholesky-space parameterisation: a single entry is not algebraically one
     pair's correlation (the correlation matrix is `cov2cor(L %*% t(L))`, a
     nonlinear function of ALL entries together), so there is no natural
     `(-1, 1)` scale to decode from. **The supplied value IS the raw working
     parameter**, unconstrained, no transform.

   `drm_phylo_mu_axis_labels()` gives axis names in the SAME order
   `log_sd_phylo` and `fit$obj$report()$phylo_q4_covariance`'s rows/columns use
   (`mu1`, `mu2`, `sigma1`, `sigma2` for a q = 4 block with only intercepts).
   `drm_phylo_mu_dense_theta_index()` maps an axis pair to its `theta_phylo`
   position for the dense case, matching TMB's Cholesky fill order.

## How the dense `theta_phylo` fill order was verified (not assumed)

Read `src/drmTMB.cpp`: the biv_gaussian dense q4 branch
(`phylo_mu_n_blocks == 1`, around line 5110) calls
`drm_qgt2_corr_matrix(theta_phylo, q_phylo, qgt2_corr_parameterization)`, which
for the default `qgt2_corr_parameterization = 0` (`drm_qgt2_corr_parameterization()`,
R/drmTMB.R) is exactly `density::UNSTRUCTURED_CORR_t<Type>(theta).cov()` -- TMB's
own standard class, replicated on the R side by `tmb_unstructured_corr_matrix()`
(fills `lower.tri()` cells in row-ascending, then column-ascending order, then
`L %*% t(L)` -> `cov2cor()`).

This was checked empirically, not just read off the source: fit the fixture,
confirm `tmb_unstructured_corr_matrix(theta_phylo)` reproduces
`cov2cor(report()$phylo_q4_covariance)` exactly (it does, to the fitted precision),
then perturb each `theta_phylo` entry one at a time from an all-zero baseline and
find which correlation-matrix cell moves. For q = 4 the order confirmed is
`(mu1,mu2)`, `(mu1,sigma1)`, `(mu2,sigma1)`, `(mu1,sigma2)`, `(mu2,sigma2)`,
`(sigma1,sigma2)` -- **not** the `combn()`-pair order `phylo_mu_pair_table()`
already uses elsewhere for REPORTING correlations (that table is filtered/permuted
differently for the block-diagonal case and is only used there to index the fully
reconstructed correlation matrix by (from_index, to_index), never to label a raw
`theta_phylo` entry by position for the dense case). Getting this order wrong would
have silently mislabelled which `theta_phylo` slot a `phylo_cor:` label writes to,
so it was worth the extra ten minutes of perturbation testing rather than trusting
the combinatorial "obviously the same order" intuition.

## Deviations from the brief

- The brief's illustrative label syntax (`phylo_sd:<axis>`, `phylo_cor:<axis1>:<axis2>`)
  is a 2-segment / 3-segment shape that does not fit design 35's existing 3-segment
  `family:dpar:target` regex. Rather than force it into 3 segments (which would have
  produced redundant labels like `phylo_sd:phylo:mu1`), `drm_parse_public_start_label()`
  now tries phylo-specific patterns FIRST, falling through to the generic pattern for
  everything else. This keeps the labels exactly as specified while keeping the
  generic vocabulary's parsing untouched.
- The dense-q4 `phylo_cor:` value is NOT on a natural `(-1, 1)` scale, unlike every
  other family (including `phylo_cor:` itself at q <= 2 or block-diagonal). This is
  documented prominently in design 35 and in the resolver's own comments, since it
  is a real asymmetry in the vocabulary, not a simplification -- there is no
  natural-scale value that would round-trip through
  `tmb_unstructured_corr_matrix()` for a single Cholesky entry in isolation.
- Scope was kept to what the A5 fixture and `phylo_mu_endpoint_dpars()` q4 dense/
  block-diagonal/q2 cases exercise. A hypothetical 3+-endpoint block-diagonal
  sub-block (the C++ `block_size == 1`/`== 2` branches only; no `== 3` case exists)
  was not built for, matching the underlying model's own scope.

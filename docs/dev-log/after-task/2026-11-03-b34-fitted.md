# After-task: batch 34, conditional fitted() and residuals() on engine = "julia" structured fits

Date: 2026-11-03. Lane: codex/general-sd-regression (private copy of 81553915d; applies to 5d4979208, which changed only evidence and review files). DRModels.jl private copy of ab8b67127.

## 1. Goal

Make `fitted()` and `residuals()` on `engine = "julia"` fits with a structured `relmat()`, `animal()` or `spatial()` mean field return the conditional mean, as native `fitted()` does, instead of the population-level value (random-effect modes at zero) documented in batch 32. Cover the Gaussian, Poisson, NB2, Gamma and Binomial routes the bridge admits where the Julia fitter can export the mode. Remove the documented difference only for routes now fixed.

## 2. Implemented

DRModels.jl (patch `b34-fitted-jl.patch`):

- `src/gaussian_core.jl`: `_attach_conditional_structured!` and `structured_conditional(fit)`. A structured fitter records `scales[:cond_eta_re]` (per-row link-scale contribution of the field at its conditional mode, data row order) and `scales[:cond_mode_k]` (inner Laplace mode of each component, first-seen group order, latent scale b with effect = sd * b).
- Fitters now record them at the converged theta from a fresh inner solve: Poisson `_fit_poisson_structured_sd_laplace` (not for phylogenetic fields), NB2 `_fit_nb2_animal_sd_laplace`, Gamma `_fit_gamma_structured_sd_laplace` (not phylogenetic), Binomial `_fit_binomial_related_sd_laplace` and `_fit_binomial_animal_q2_laplace` (two modes), Gaussian `_fit_structured_gaussian_lss` when `report_sd` (the exported mode is `blup ./ sd_group`).
- `src/bridge.jl`: `_bridge_flatten` ships `conditional_structured = {kind, eta_re, modes}`; `_bridge_dpars` skips `cond_*` keys. DRModels.jl's own `fitted()` and `residuals()` are unchanged.

drmTMB:

- `R/julia-bridge.R`: `drm_julia_conditional_structured_plain()` parses the payload into `fit$conditional_structured`; `drm_julia_conditional_structured_fitted()` rebuilds `linkinv(linkfun(population mean) + eta_re)` for identity, log, logit, probit and cloglog links, and refuses a payload whose length does not match the fit. `fitted.drmTMB_julia` uses it through `drm_julia_fitted_recomputed()`; `residuals.drmTMB_julia` is re-based as before (`y - fitted`).
- `NEWS.md` and `docs/dev-log/known-limitations.md`: the documented difference is removed for the routes below only.

Routes changed (each tested on a shuffled-row fixture): Gaussian relmat, animal, spatial intercept and relmat, animal, spatial slope; Poisson relmat, animal, spatial intercept and relmat, animal slope, plus animal `Ainv`; NB2 relmat, animal, spatial intercept and relmat, animal, spatial slope; Gamma relmat, animal, spatial intercept and relmat, spatial slope; Binomial relmat, animal, spatial intercept and relmat, animal, spatial slope (logit), relmat probit, animal cloglog, animal `Ainv`, and the animal q2 intercept-plus-slope block.

## 3a. Decisions and Rejected Alternatives

- Export a per-row `eta_re` next to the modes. The R side then needs no loading, weight, slope or SD-scale logic, so row order cannot be mis-mapped. Rejected: rebuilding the field in R from the modes and a re-derived loading, which would copy each fitter's parametrisation.
- Capture the mode from a fresh inner solve at theta-hat, not from the warm-start cache (`last_b`), which the finite-difference stencils move.
- Phylogenetic fields are not exported: the task scope was relmat, animal and spatial and no phylogenetic fixture was run.
- Rejected: rebuilding the mean by refitting or evaluating native TMB at the Julia estimates. It would make the native comparison circular.
- Assumptions made without asking: (1) `predict()` on stored rows is left population level (task named `fitted()` and `residuals()` only); if wrong, `drm_julia_predict_*` would read the same payload. (2) The Gaussian REML route does not export (guarded by `!reml`; that route is not a structured SD route). (3) Tolerances 1e-4 relative on fitted and residuals, 1e-6 on modes, chosen before the runs.

## 7a. Issue Ledger

- Fixed: `fitted()` and `residuals()` on the listed structured Julia routes were population level.
- Fixed in review of my own change: the NB2 fitter overwrote the boxed `value` (log-likelihood off by 28) until the mode solve was moved before it.
- Found, not fixed: the NB2 fitter stores `-value` from a variable shared by its closures, so its stored log-likelihood is the last finite-difference `nll` call, a point within about 1e-5 of theta-hat, not exactly `nll(theta_hat)`; harmless here but it is why the new log-likelihood check uses 1e-4. Native TMB and Julia reach different optima on the Binomial animal q2 fixture (native logLik -504.86, Julia -500.38); the q2 check therefore uses an independent dense solve at the Julia estimates.
- Deferred: `predict()` on stored rows for these fits is still population level, so it no longer equals `fitted()` on the changed routes.

## 9. What Did Not Go Smoothly

- The first NB2 edit silently changed the log-likelihood (shared boxed `value`).
- Binomial animal q2: native and Julia disagree on the optimum, so a native comparison was not possible.
- A first Julia test tolerance (1e-9 on `loglik == -nll(theta)`) was wrong by design (warm-start noise up to 1e-5); it is now 1e-4, still far below the 28 it guards against.
- NB2 fixtures near the dispersion plateau (log sigma below -4) disagree with a 1/sigma^2 oracle because the fitter clamps the NB2 size; the test fixture now requires an interior sigma.

## 11. Team Learning

A closure that assigns a name also assigned by its enclosing function shares one boxed variable; a new call to that closure after the objective is read silently rewrites the objective. Take any extra inner solve before the line that stores the objective, and add a test that compares the stored log-likelihood with `nll(theta_hat)`.

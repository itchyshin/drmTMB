# After Task: `biv_lognormal` admitted through `engine = "julia"`

## 1. Goal

Admit drmTMB's native `biv_lognormal()` on the `engine = "julia"` fixed-effect
bivariate-residual route, and settle by measurement -- not assumption -- which
scale the response and the `sigma` dpars live on across the two engines. A
lognormal bridge fit that disagreed about the scale would still return finite,
plausible-looking coefficients, so engine-vs-engine agreement alone cannot
establish it.

## 2. Implemented

Two changes, both minimal:

* `R/julia-family-registry.R`: one row, `spec("biv_lognormal", fe = TRUE)`.
* `R/julia-bridge.R`: `drm_julia_bridge_default_dpar_labels()`'s bivariate
  branch now matches the `biv_` PREFIX instead of the single literal
  `"biv_gaussian"`; and one `drm_julia_capability_comparison()` row
  (`fe_biv_lognormal`) across its ten parallel columns.

The label change was measured into existence, not guessed. With the registry
row alone, **both** the full and the short formula abort inside DRM.jl with
`coef_labels supplies names for unknown dpar "sigma"; the model has dpars: mu1,
mu2, sigma1, sigma2, rho12` -- the univariate branch was adding a scalar `sigma`
label to a model whose blocks are `sigma1`/`sigma2`/`rho12`, and design 258's
fail-closed echo correctly refused it.

No DRM.jl change was needed: `_bridge_family()` already maps the tag
`biv_lognormal` to `LogNormal()` at pin 430ef64cc, and the pin clone's `src/`
and `Project.toml` are unmodified (verified, 0 changed files).

## 3. Mathematical Contract

Both engines take `y1`/`y2` on the RAW positive scale and log them internally
(native `drm_build_biv_lognormal_spec()`; DRM.jl `src/bivariate_lognormal.jl`),
and the bridge passes the response through untouched. So `mu1`/`mu2` are means
of `log y` (identity link), `sigma1`/`sigma2` are SDs of `log y` (log link,
reported on the response scale as `exp()` of the coefficient), `rho12` is the
LOG-residual correlation, and both engines add the parameter-free
change-of-variables Jacobian `-sum(log y1) - sum(log y2)`.

Measured on the n = 80 seed-6301 draw: `exp(sigma1_(Intercept)) = 0.452813735`
equals both engines' `predict(dpar = "sigma1")`; fitted `mu1` averages to
`mean(log y1) = 0.22974856`; and both engines' `logLik` (-164.673669588) equals
the independent raw-scale oracle of `tests/testthat/test-biv-lognormal.R` to
4e-13, so both carry the Jacobian (-22.18410807 on this draw).

## 3a. Decisions and Rejected Alternatives

* **Prefix, not a family list.** The bivariate branch could have gained a
  literal `"biv_lognormal"`. The prefix was chosen because it is the convention
  `drm_julia_fe_only_fence_families()` already uses for the bivariate
  exemption, and because a scalar `sigma` block is wrong for *every* bivariate
  family, not just this one. A bivariate family with an EXTRA dpar (a shared
  `nu`) still needs its own default row, and the comment says so.
* **Rejected: widening beyond fixed effects.** Native
  `drm_build_biv_lognormal_spec()` itself refuses random effects, structured
  markers, `meta_V`, offsets, `weights` and predictor-driven
  `sigma1`/`sigma2`/`rho12`. There is no native comparator for any other cell,
  so no other cell could be measured, so none is claimed.

## 11. Team Learning

For any family whose response is transformed inside the engine, the
engine-vs-engine receipt is necessary but not sufficient. Both engines could be
wrong the same way. The cheap discriminating control is to fit the *untransformed*
sibling family on the same data and show the log-likelihood moves by exactly the
Jacobian -- here `biv_gaussian()` on logged responses reproduced the
`biv_lognormal` log-likelihood minus the Jacobian to the last digit, which no
scale mix-up could have survived.

## 12. Cross-Product Coverage

`sigma1`/`sigma2`/`rho12`, both the full and the short formula spelling.
NOT admitted and NOT claimed: random effects, `phylo()`, structured markers,
`meta_V`, offsets, `weights`, predictor-driven `sigma1`/`sigma2`/`rho12`,
REML, interval coverage, bridge-side profile/bootstrap intervals.

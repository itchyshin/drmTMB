main's general mechanism defer to a family-specific fence — that is

## 6. Tests of the Tests

The generator is the oracle that matters here, and it earned that twice. A
column-wise data frame with one short column is a MISALIGNED table, not an
obvious error — `route[i]` would simply stop describing `capability_id[i]`. Both
times, `data.frame()` refused with `arguments imply differing number of rows`
rather than producing a plausible wrong table.

Two guards were added to the resolver *because* the session tripped them:

- **Lost-definition guard.** Resolving conflicts to main silently dropped
  `drm_julia_refuse_biv_lognormal_unsupported()` in #1216 while leaving its call
  site standing. The resolver now diffs top-level definitions before and after
  and refuses the merge if any branch definition vanishes.
- **Collision guard and uniqueness assertion.** Before substituting a cell, the
  old value must occur exactly once; if both sides edited the same cell the merge
  stops rather than guessing.

Both guards are negative checks that were observed to fire on a real defect, not
asserted to work.

## 9. What Did Not Go Smoothly

Five real mistakes, all mine, all caught by machinery rather than by reading:

1. **A merge ran in the Dropbox main checkout.** A `cd` to a worktree failed
   (the worktree existed under a different name) and the FOLLOWING lines were not
   chained to it, so `git merge origin/main` executed in the main checkout.
   `git merge --abort` then failed on a stale stat-cache entry
   (`docs/dev-log/check-log.md` "not uptodate" — Dropbox touching mtimes).
   Recovered fully: backed up all uncommitted state first, then
   `git update-index --refresh` and abort. HEAD unchanged, zero tracked
   modifications. Everything after this uses `git -C` so the working directory
   cannot matter.

2. **The resolver patched the wrong function.** `route`, `syntax`,
   `drmjl_status` and `evidence_url` appear TWICE in `R/julia-bridge.R` — once in
   `drm_julia_intentional_gates()` and once in the capability table. A
   first-occurrence regex hit the gate registry. Caught by the generator
   (`31, 30`), redone scoped to the text after the capability-function anchor.

3. **The batch resolver could discard its own work.** `git checkout --theirs` on
   a still-unmerged file overwrites the worktree copy — i.e. the resolution just
   written. Fixed by staging resolved source first and restricting `--theirs` to
   generated files. #1215 was the one PR that ran under the unfixed script; it
   was checked and is intact.

4. **A whole function was dropped by resolving to main** (#1216), leaving its
   call site standing. Now guarded; see §6.

5. **A reported "MERGED" that was not.** Reported to the DRM.jl session that a
   watcher would re-run #656's failed job. It never got the chance — the workflow
   still had a job in flight, and the head moved when the owner pushed. The green
   there is the owner's commit, not a re-run of mine. Corrected in a follow-up
   message rather than left standing.

**The #656 diagnosis.** A peer session reported #656 red on Julia 1.10 shard 1/4
(`contractions == 1`, expected 0) and argued, with evidence, that the branch was
the likely cause. It was not, and the measurement chain matters more than the

## 9c. Two structural fixes, both measured

**DRM.jl's docs treadmill (#750, merged).** The required `docs` job sat in a
one-slot repo-wide concurrency group, so every merge to main evicted the other PRs'
pending docs runs and exactly one PR could clear per cycle. #750 makes the group
per-ref. Confirmed by observation afterwards: **four Documenter runs in progress
simultaneously** on four different branches, where before only one could run.

**drmTMB's per-merge cost.** `R-CMD-check` ran on push-to-main as well as
pull_request: **25 full sharded runs in one day**, re-checking content the PR run
had already checked. Switched to `[pull_request, workflow_dispatch]` on the owner's
instruction, deliberately KEEPING `push: tags: ["v*"]` — that trigger is not the
per-merge cost, it is the full ubuntu+macOS+Windows release matrix, and dropping
`push:` wholesale would have removed it silently. Consequence stated rather than
hidden: there is no post-merge run on main any more, so the merge-gate step that
reads main's own run has nothing to read; verification moves entirely to the PR.

**R-hub was never ours.** Six red runs since 2026-08-09. In every one, clang-asan,
gcc-asan and clang-ubsan PASS and only `rchk` fails — with 12 findings, all in
`TMB/include/tmb_core.hpp`, and 0 in `src/` or `inst/include/`. The five
"too many states (abstraction error?)" lines are the analyzer giving up, three of
them inside R's own base C. `tools/rchk-triage.sh` (#1294, merged) answers the only
useful question — *does rchk name a file we own?* — in seconds, and ships a red
control that flips its verdict on a synthetic finding.

## 11. Team Learning

**A dependency declared on a PR NUMBER does not hold when another PR carries the
same CONTENT.** Recorded earlier in this lane; it held again today.

**Generated artifacts couple otherwise independent PRs.** Every merge to main
makes the others' committed copies stale, and the source-tree blind-spot lane
catches it. This is why the drain must be serial: merge one, refresh the rest.
It is the same shape as DRM.jl's one-slot docs concurrency group, in a different
costume.

**A count that varies by runner is a platform property, not a regression** — and
pinning it re-pins the platform difference the guard exists to absorb. That is
the owner's framing of #651/#616 and it generalises.

**Prefer the parsed oracle to the read diff.** Every conflict resolution this
session that was decided by reading was wrong at least once; every one decided by
parsing both sides and asserting invariants was right. The generator refusing to
build a misaligned table is worth more than careful reading of eleven conflict
blocks.

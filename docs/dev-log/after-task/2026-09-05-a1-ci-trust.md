## Purpose

A green run must carry evidence. Three ways it did not:

1. **#1083** -- the Route-C parity test converted a fit ERROR into a skip.
2. **#1081** -- a green run said nothing countable about whether the bridge
   glue executed; its teardown line reads "bridge glue is UNTESTED".

## What changed (three files, one new)

- `tools/ci-receipt-staleness.sh` (new). Detects, never regenerates. Runs
  `python3 tools/capability_ledger.py --check-c14-receipt-equivalence` (the
  C17 checker) and compares, for every
  `docs/dev-log/evidence/julia-r-parity/lss-tip-identity/public-NNN.json`,
  the SHA-256 of each pinned `R/*.R` path and of the runner
  `tools/run-julia-phylo-labels-public.R` with the receipt's `source_before`
  -- the R-side half of the checker's `--current` mode, byte-identical
  semantics -- plus `status == PASS`, `source_unchanged`, key parity, and
  any `R/*.R` file present now but not pinned. It then runs the R checker
  WITHOUT `--current` for internal consistency when `jsonlite` and `digest`
  are installed (neither is in DESCRIPTION), and says so when it did not.
- `.github/workflows/R-CMD-check.yaml`. Two Linux-only steps between
  "Evidence citations resolve" and `check-r-package`: **Receipt staleness
  (detect, never regenerate)** runs the script; **Julia bridge glue executes
  (mock-driven, no Julia)** runs eleven mock-driven bridge test files under
  `pkgload::load_all()`, prints a per-file and total tally, and fails unless
  `> 0` passed with `0` failures and `0` errors. `concurrency` untouched.
- `docs/dev-log/after-task/2026-09-05-a1-ci-trust.md` (this file).

`tests/testthat/test-julia-tmb-parity.R` is in OWNS but is **unchanged**:
the #1083 fix is already on `origin/main` (450ab650e "stop converting
live-engine errors into skips (#1127)", 1c7ec1efd), as `drm_parity_run()` +
`drm_parity_run_error_handler()`, which skips only on the eight

## Findings that changed the design while building it

1. **`capability_ledger.py --check` does NOT check the C17 receipt.** A
   byte appended to `R/methods.R` passed `--check`; the whole-file blob
   comparison lives behind `--check-c14-receipt-equivalence`, which CI
   reaches only via `tools/tests/test_capability_ledger.py`. The script
   calls the flag by name. Caught by the red control, not by reading.
2. **`check-julia-phylo-labels-receipt.R --current` cannot run on a CI
   runner.** The receipt manifest pins every DRM.jl `src/*.jl` file by the
   ABSOLUTE path of the clone that produced it (public-001.json:
   `/private/tmp/.../scratchpad/drmjl-objat/src/*.jl`, 94 of its 142 keys),
   and the checker fails closed on the first absent path. #1150's premise
   that the hash comparison "needs no Julia" is true only of the R side.
   The script does that half itself. A `--current-r-only` flag on the
   checker (owner: whoever owns `tools/check-julia-phylo-labels-receipt.R`)
   would let the script call the real checker instead of re-implementing
   48 hash comparisons; the semantics are identical today.
3. **The two `phylo-labels/public-00{1,2}.json` receipts are staler still**
   (`R/check.R` differs; same absolute-path pinning). They are not the
   receipt #1150 names and the script does not grade them; recorded so
   nobody reads their `PASS` status as current.
4. **The bridge glue was never 0% executed in CI.** #1081's "0%" is about
   the LIVE call; 1212 mock-driven expectations across eleven files already
   ran in every sharded job. What was missing was a counted, failing claim
   about it -- and the teardown line saying "UNTESTED" over the top of it.

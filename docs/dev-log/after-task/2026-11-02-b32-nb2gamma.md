# After-task report: batch 32, labelled q2 SD blocks for native NB2 phylo and Gamma relmat and phylo

Date: 2026-11-02. Reader: Shinichi, and the next agent on the general-sd-regression lane.

## 1. Goal

Batch 31 found that native drmTMB refuses the labelled `(1 + x | p | id)` form, with
one `sd()` formula per coefficient, for NB2 `phylo()`, Gamma `relmat()` and Gamma
`phylo()`. For each route, find out why, and admit it if the refusal is only an R-side
gate or a missing provider-to-kernel mapping.

## 2. Implemented

All three routes were R-side gates; no C++ was written or changed. The C++ template for
model types 5 (Gamma) and 6 (NB2) already carries the labelled q2 prior
(`has_phylo_mu_q2_covariance`, `src/drmTMB.cpp` around lines 3629 and 5307), and the R
data builder, `split_tmb_corpars` and the `eta_cor_phylo` map already list `nbinom2` and
`gamma`.

`R/drmTMB.R` (three narrow edits):

- NB2: `allow_nb2_structured_q2_sd` (around line 11148) demanded
  `is.null(covariance_label)` for `phylo`. It now admits `phylo` with a label, like
  `animal` and `relmat`; `spatial` keeps the unlabelled-only condition. The later
  `validate_count_structured_mu_term` call already listed `phylo` among the labelled
  intercept-plus-slope types.
- Gamma phylo: `validate_positive_continuous_mu_structured_term` refused any label on a
  phylo intercept-plus-slope term. It now lets a label through for exactly one
  `(Intercept)` plus one numeric slope. A labelled slope-only term is still refused. The
  existing check in the Gamma spec builder (labelled without `sd()` formulas) fires after
  that and still refuses the unpaired case.
- Gamma relmat: `validate_gamma_relmat_mu_structured_term` got the same condition.

The kernel comes from the existing providers: relmat uses `K` as supplied (or `Q`), phylo
uses the package tip-covariance helper (a correlation matrix). Fit, `fit$corpars`,
`predict(dpar = ...)`, the per-group SD output and `simulate(re.form = NA)` already
used the generic labelled-q2 path and needed no change.

## 6. Tests of the Tests

Emulated bugs, each required to move the oracle by more than 0.1 log-likelihood units
(tolerance for agreement is 1e-4): swapped SD formulas, reversed SD vector, rho dropped to
0, rho sign flipped, kernel read by level position, plus `cov2cor(K)` and the supplied
kernel order by position for relmat, and the raw `ape::vcv` (not a correlation) and the
kernel in tree tip order for phylo. The smallest gap was 1.26 for NB2 (raw `vcv`) and
0.76 for Gamma (raw `vcv`). A call-level swap of the two SD predictors is also fitted and
changes the log-likelihood by more than 0.1. The hand tree kernel `cov2cor(ape::vcv)` is
compared with the package helper to 1e-8. SD predictors are not palindromic (asserted),
kernel rows differ in order from the data levels (asserted), and the relmat kernel has a
non-unit diagonal (asserted). `fit$corpars` holds the one estimated correlation
(`cor(mu:(Intercept),mu:x | p | id)`), equals the reported `rho_phylo`, and moves with
the data: true rho 0.8 against -0.8 on the same design gives estimates that differ by
more than 0.4.

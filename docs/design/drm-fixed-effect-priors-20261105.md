# Fixed-effect normal priors and ridge penalties

This first slice helps applied users regularize separation and unstable coefficients in ordinary fixed-effect Gaussian and binomial-logit models. Priors select the actual design-matrix column within a named distributional parameter. Random effects, other families, SD priors and posterior sampling are outside this slice.

For distributional parameter d, eta_d = X_d beta_d + offset_d. Gaussian mu uses an identity link; Gaussian sigma uses a log link. A prior on a sigma coefficient therefore acts on log-scale regression coefficients, not on each observation's positive residual SD. Binomial mu uses a logit link. No predictor rescaling occurs.

For a selected beta_j, normal(mean m_j, SD s_j) adds `0.5 * ((beta_j-m_j)/s_j)^2 + log(s_j) + 0.5*log(2*pi)` to the negative data log-likelihood. Its gradient is `(beta_j-m_j)/s_j^2` and diagonal Hessian is `1/s_j^2`. A ridge penalty adds `0.5*lambda*beta_j^2`, with gradient `lambda*beta_j`. It has the same optimum and curvature as a mean-zero normal with SD `1/sqrt(lambda)`; its objective omits the normal density constant. Zero lambda contributes nothing and leaves the estimator labelled ML, while still validating the selector and design rank.

Use `drm_priors(drm_prior_normal("mu", "x", sd = 2))`. For every `coef = "all"` selector, specify `intercept = "include"` or `"exclude"`. Exact column names are literal; `drm_resolve_priors()` previews them. The resolver uses design assignment metadata for a conventional intercept. No-intercept factor level columns remain ordinary coefficients. Unknown names, overlapping selectors, missing model variables, aliased columns and empty selections fail before fitting. Intercepts and slopes may have different prior means and SDs.

The compiled TMB objective receives zero-based block and column indices plus mean, SD and normalization flags. Its single final prior addition applies to all admitted routes. Empty vectors add zero on the no-prior route. Gaussian and binomial builders receive those empty defaults even when used below the public fitter. No likelihood parameterization or formula grammar changes.

An active prior yields a penalized/MAP fit. The object stores `priors`, `resolved_priors`, `fixed_prior_penalty`, `penalized_objective`, `prior_gradient` and `likelihood_gradient`. The usual convergence gradient is the penalized score. The data-only score need not vanish at MAP. `logLik()` and `objective_at()` exclude the prior contribution at the evaluated point. Covariance from the penalized Hessian is local posterior curvature under the stated coefficient prior; neither interval calibration nor a proper full posterior is established. Confidence intervals, profile likelihood, bootstrap intervals and ordinary AIC/BIC/LRT comparisons refuse active fixed priors. Point predictions and plug-in simulations remain available and do not sample coefficient uncertainty.

Fits with active priors use an unclamped Gaussian log-scale predictor. For ordinary optimizer-list controls, the prior fitter disables the default clamp before fitting. Users passing a `drm_control()` object must set `logsigma_clamp = NULL` explicitly; a configured clamp refuses. Unit weights, dense nonaggregated design matrices, complete model data, ML mode, and no existing phylogenetic penalty are required. Native Julia and the bridge must reject corresponding unsupported routes rather than silently ignore a prior.

The Julia implementation is fresh MIT code. The R implementation is a fresh implementation of the equations; gllvmTMB commit `092fcee6e` informed the selector, derivative and reporting review. No GPL source is copied into Julia. The [glmmTMB prior vignette](https://glmmtmb.github.io/glmmTMB/articles/priors.html) supplies an external comparator pattern. Shared syntax and objectives are design targets; only measured source-pinned fixtures support numerical agreement.

Validation uses direct Gaussian/binomial densities, independent finite differences, the exact conditional Gaussian ridge solution, separation and known-data-generating-coefficient fixtures, and update/reporting refusal tests. Each engine must pass its own oracle before pairwise comparison. See `docs/dev-log/priors-lane-20261105/` for source pins, failures, review and final evidence. SD priors and tmbstan require separate design and validation.
